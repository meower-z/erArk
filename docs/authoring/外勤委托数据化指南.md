# 外勤委托数据化指南

本指南说明如何将活动或章节剧情文本整理并转化为 `data/csv/Commission.csv` 中的外勤委托条目。

## 输入文件

- 剧情原文：本地目录 `data/data_from_game/<章节名>/*.txt`（已被 .gitignore 忽略，不随仓库分发，需自行放入）。编写委托前可先按关卡顺序整理要点化的 `data/data_from_game/<章节名>/剧情总结.md`，记录概述、主要角色与阵营、时间线、各关卡的场景/冲突/发展/结果与对白摘要及关卡要点速查。
- 目标数据表：`data/csv/Commission.csv`。
- 编号字典表：`data/csv/Resource.csv`（资源）、`data/csv/Ability.csv`（能力）、`data/csv/Experience.csv`（经验）、`data/csv/Juel.csv`（宝珠）、`data/csv/Talent.csv`（素质）、`data/csv/Nation.csv`（势力）、`data/csv/Birthplace.csv`（国家/出生地）。

## CSV 列顺序与基础字段

`data/csv/Commission.csv` 表头固定为 12 列，新增行须严格按此顺序填写：

```text
cid,name,country_id,level,type,people,time,demand,reward,related_id,special,description
```

- `cid`：唯一整数编号，新增前先查 `data/csv/Commission.csv`，在所用号段当前最大值之后挑选未占用编号（同一活动建议连续）。重复 `cid` 会在加载时静默覆盖先前的行。
- `country_id`：`-1` 为通用委托，其余填所属国家编号。
- `level`、`people`、`time`：委托等级、派遣人数与耗时天数（非调试模式下仅显示 `level <= 设施 14 等级 + 1` 的委托）。
- `type`：现有取值包括 `资源`、`源石`、`成长`、`势力`、`角色`、`技能`、`支线`（临时追捕委托另见 `追捕`），剧情类委托建议填 `支线`。当 `type` 为 `角色` 且 `demand` 含 `c_` 项时，`c_` 项须放在 `demand` 第一项，`_0` 与 `_1` 均合法。该项中的 `adv` 决定非调试模式下是否显示（须有对应干员在 `roster.active()` 中），尾部的 `0` 或 `1` 决定该干员禁止出勤还是必须出勤。
- `related_id`：用于串联剧情进度链。首条委托填 `-1`，后续委托填前置委托的 `cid`（前置未完成时不显示）。
- `special`：`0` 为可重复接取的常规外勤，非 `0`（剧情类填 `1`）归入「特殊外勤」且仅可完成一次。

## 需求与奖励语法

`demand` 与 `reward` 字段以 `&` 连接多项，无需求时填 `无`。各项遵循 `前缀_编号_数值` 格式，对应解析逻辑位于 `Script/System/Field_Commission_System/field_commission_function.py` 的 `process_commission_text` 与 `get_commission_demand_and_reward`：

| 前缀 | 格式与含义 | 需求 / 奖励行为 |
| --- | --- | --- |
| `r` | `r_<资源id>_<数量>` | 需求扣除库存，奖励增加库存 |
| `a` | `a_<能力id>_<等级和>` | 仅作需求判定，按派遣队员经装备修正后的能力值之和核对（完美维护且低于 8 时加 1，中度损坏且大于 0 时减 1，如 `a_40` 话术、`a_41` 指挥、`a_42` 战斗、`a_45` 学识、`a_46` 医术、`a_48` 制造） |
| `e` | `e_<经验id>_<数值>` | 需求按队员之和判定，奖励发给全部派遣队员（如 `e_80` 对话、`e_81` 战斗、`e_82` 学识、`e_87` 指挥、`e_88` 医疗、`e_90` 制造） |
| `j` | `j_<宝珠id>_<数值>` | 需求按队员之和判定，奖励发给全部派遣队员 |
| `t` | `t_<素质id>_<数值>` | 需求按队员之和判定，奖励时正数设为 1、负数设为 0 |
| `c` | `c_<角色adv编号>_<数值>` | 需求时 `1` 为必须出勤、其余值（数据中常用 `0`）为禁止出勤，奖励时将未招募的该干员加入待确认招募名单 |
| `m` | `m_<委托id>_<状态>` | 奖励时改写委托标记：`-1` 标为不可进行，`1` 标为已完成，`0` 每次只移除一项标记（先去不可进行，否则去已完成）。特殊委托（`special != 0`）若同时带有两项标记，单次 `0` 后仍保留已完成标记且继续隐藏 |
| `特产` | `特产_0_<数量>` | 对应当前所在国家特产，需求按库存判定，奖励入库 |
| `声望` | `声望_<势力id>_<百分值>` | `0` 为当前国家所属势力，实际值为数值乘 `0.01`，需求不扣除、奖励增加 |
| `好感` | `好感_<角色adv编号>_<数值>` | 角色对玩家的好感度，需求判定或奖励增加 |
| `信赖` | `信赖_<角色adv编号>_<数值>` | 角色信赖度，需求判定或奖励增加 |
| `攻略` | `攻略_<角色adv编号>_<等级>` | 角色攻略程度，仅作需求判定 |
| `招募` | `招募_<角色adv编号>_<0或1>` | 仅作需求判定：`1` 要求已招募该干员；`0` 只显示为「未招募」，不会阻止接取 |
| `追捕` | `追捕_<角色id>_1`（角色 id，不是 adv 编号） | 只由 `create_capture_fugitive_commission` 为临时追捕委托生成，不要手写；结算时如果有空的关押宿舍，就收押该角色 |

## 描述规范

- `description` 用 2 至 4 句话概括行动目标与关键节点经过，每句不少于 50 个中文字符，风格与现有支线委托一致。
- 换行写成字面 `\n`，描述正文中不要出现英文逗号（改用中文逗号），避免破坏 CSV 分列。

## 质量检查与构建

- 核对每条新增记录均为 12 列、`cid` 无冲突、`related_id` 指向已存在编号或 `-1`、`demand` 与 `reward` 前缀合法且无多余空格。
- 在仓库根目录运行 `python buildconfig.py` 重新生成配置，确认无 `KeyError` 或字段缺失错误，必要时启动游戏在外勤委托面板核对显示。
