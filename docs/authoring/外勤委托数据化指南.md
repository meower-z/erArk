# 外勤委托数据化指南

本指南说明如何编写 `data/csv/Commission.csv` 中的外勤委托数据，包括输入文件、表头与基础字段、`demand` 与 `reward` 语法、描述编写约定及构建检查步骤。

## 输入文件

- 剧情原文位于本地目录 `data/data_from_game/<章节名>/*.txt`。该目录已在 `.gitignore` 中忽略，不随仓库分发，需作者自行放入本地。编写委托前可先按关卡顺序整理 `data/data_from_game/<章节名>/剧情总结.md`，梳理场景、角色、事件经过与关键节点。
- 目标数据表为 `data/csv/Commission.csv`。
- 常用编号字典表包括 `data/csv/Resource.csv`（资源）、`data/csv/Ability.csv`（能力）、`data/csv/Experience.csv`（经验）、`data/csv/Juel.csv`（宝珠）、`data/csv/Talent.csv`（素质）、`data/csv/Nation.csv`（势力）与 `data/csv/Birthplace.csv`（国家/出生地）。

## CSV 表头与基础字段

`data/csv/Commission.csv` 固定为 12 列。第 1 行表头如下：

```text
cid,name,country_id,level,type,people,time,demand,reward,related_id,special,description
```

第 2 至第 5 行依次为中文列说明、列类型（`int,str,int,int,str,int,int,str,str,int,int,str`）、翻译开关与表标题行，新增数据应追加在数据区末尾。

各基础字段的含义与读取规则如下：

- `cid`（整数）：委托编号。新增前请先查看 `data/csv/Commission.csv`，避开已占用的号段（例如 `3030` 至 `3045` 为现有的「喧闹法则」支线委托链），挑选未使用的整数编号。加载器 `Script/Config/game_config.py` 的 `load_commission` 读到重复 `cid` 时不会报错，而是用后一行覆盖前一行在配置表中的条目。同时，每条重复行都会把该 `cid` 追加进按国家索引的列表。编号 `10001` 及以上由运行时函数 `create_temp_commission` 创建临时委托时使用（自动跳过已有编号，并将新行直接追加写入 `data/csv/Commission.csv`），手写数据应避免占用该号段。
- `name`（字符串）：委托名称，显示在外勤委托列表与详情页中。
- `country_id`（整数）：所属国家编号，对应 `data/csv/Birthplace.csv` 的 `cid`。填 `-1` 表示通用委托。外勤委托面板会列出罗德岛当前所在国家（`location.country()`）的委托以及 `country_id` 为 `-1` 的通用委托。
- `level`（整数）：委托等级。非调试模式下，面板会隐藏 `level` 大于「机库（设施编号 `14`）等级加 `1`」的委托。
- `type`（字符串）：委托类型。现有数据中的取值包括 `支线`、`技能`、`资源`、`势力`、`角色`、`源石`、`成长`，运行时生成的追捕委托使用 `追捕`。剧情类委托按现有惯例填 `支线`。当 `type` 为 `角色` 且 `demand` 含有 `c_` 项时，`c_` 项必须放在 `demand` 的第一项，且 `c_<adv>_0` 与 `c_<adv>_1` 均可作为第一项。非调试模式下，面板只读取第一项中的角色 `adv` 编号，只有当在编干员名单（`roster.active()`）中存在对应干员时才会显示该委托。
- `people`（整数）与 `time`（整数）：`people` 为所需派遣人数。「执行委托」按钮在队伍人数不少于 `people`、载具总运载量达标且 `demand` 校验通过时才会启用。`time` 为基础耗时天数。派遣载具的总运载量（`data/csv/Vehicle.csv` 中各载具 `capacity` 乘以数量之和）须不少于 `(time - 1) × people`，因此 `time` 为 `1` 时不需要载具。派遣时取最慢载具的 `speed`（未派遣载具时按 `1` 计）。若该速度大于 `1`，实际耗时改为 `time × 1440 × 0.9^速度` 分钟（向下取整）。若该速度不大于 `1`，实际耗时保持基础天数不变。
- `demand` 与 `reward`（字符串）：需求与奖励表达式，详见下节。委托编号 `1104` 在代码中有硬编码的额外奖励（载具编号 `51`），不由 CSV 的 `reward` 字段驱动。
- `related_id`（整数）：前置委托编号，用于串联剧情链。无前置时填 `-1`，有前置时填前置委托的 `cid`。非调试模式下，前置委托尚未完成时当前委托会被隐藏。
- `special`（整数）：委托页签与重复规则标记。`0` 显示在「常规外勤」页签，可重复接取。非 `0`（剧情类委托通常填 `1`）显示在「特殊外勤」页签，非调试模式下完成后即隐藏。另外，位于不可进行名单（`commission.shut_down()`）中的委托在非调试模式下也会隐藏。
- `description`（字符串）：委托介绍文本，详见「描述规范」一节。

## 需求与奖励语法

`demand` 与 `reward` 由 `Script/System/Field_Commission_System/field_commission_function.py` 中的 `get_commission_demand_and_reward` 与 `process_commission_text` 解析。多项之间用 `&` 连接，无需求或无奖励时填 `无`（需求为 `无` 时恒通过）。除 `无` 以外，每一项均按 `_` 切分为 `前缀_编号_数值` 三段，其中 `编号` 与 `数值` 必须都是整数。

面板在挑选派遣队伍时实时校验 `demand`，某项当前值小于需求值时判定为不满足。带消耗的需求项在确认派遣时扣除一次。每个 `r_` 需求项都会独立核对当前库存并在派遣时按序独立扣除，不会把重复的资源编号合并累加（例如库存为 `7` 时，`r_22_5&r_22_5` 会通过校验但在派遣时仅扣除 `5`），因此同一资源编号须合并写为一项。`reward` 在委托到期完成时由 `judge_field_commission_finish` 统一结算，随后将该委托记入已完成名单（`commission.mark(cid, 1)`）。

| 前缀 | 格式 | 需求与奖励行为 |
| --- | --- | --- |
| `r` | `r_<资源id>_<数量>` | 需求核对仓库库存并在派遣时扣除，奖励按数量增加库存 |
| `a` | `a_<能力id>_<等级和>` | 仅作需求判定，按派遣队员经装备修正后的该能力值之和核对。单名队员装备状态大于等于 `2`（完美保养）且该能力低于 `8` 时加 `1`，装备状态低于 `-1`（中度损坏或更重）且该能力大于 `0` 时减 `1`。常见能力如 `a_40`（话术技能）、`a_41`（指挥技能）、`a_42`（战斗技能）、`a_45`（学识技能）、`a_46`（医术技能）、`a_48`（制造技能） |
| `e` | `e_<经验id>_<数值>` | 需求按派遣队员该经验值之和判定，奖励将该数值加给每一名派遣队员。常见经验如 `e_80`（对话经验）、`e_81`（战斗经验）、`e_82`（学识经验）、`e_87`（指挥经验）、`e_88`（医疗经验）、`e_90`（制造经验） |
| `j` | `j_<宝珠id>_<数值>` | 需求按派遣队员该宝珠数量之和判定，奖励将该数值加给每一名派遣队员 |
| `t` | `t_<素质id>_<数值>` | 需求按派遣队员该素质值之和判定。奖励作用于每一名派遣队员，数值大于 `0` 时将该素质设为 `1`，小于 `0` 时设为 `0`，等于 `0` 时不变 |
| `c` | `c_<adv编号>_<值>` | `<adv编号>` 经 `get_character_id_from_adv` 映射为角色 id。需求侧 `1` 表示必须出勤，`0` 表示禁止出勤（建议仅填 `0` 或 `1`，详见表下说明）。奖励侧当该干员不在在编名单且未处于离线状态时，将其加入待确认招募名单（`recruit.pending()`） |
| `m` | `m_<委托id>_<状态>` | 仅作奖励结算，调用 `commission.mark(id, state)` 改写委托标记：`-1` 加入不可进行名单，`1` 加入已完成名单，`0` 每次调用仅移除一项标记（优先移除不可进行，否则移除已完成），其他值不改动状态 |
| `特产` | `特产_0_<数量>` | 对应求值时罗德岛所在国家配置的第一项特产，需求仅核对库存而不扣除，奖励在委托完成时按当时所在国家入库。无特产国家的回退规则见表下说明 |
| `声望` | `声望_<势力id>_<百分值>` | 实际值为所填整数乘以 `0.01`。势力编号见 `data/csv/Nation.csv`。编号填 `0` 时按罗德岛当前所在国家匹配首个顶层势力。需求仅核对当前声望而不扣除。奖励按实际值增加声望。无匹配势力时的回退规则见表下说明 |
| `好感` | `好感_<adv编号>_<数值>` | 对应角色对玩家的好感度（`favorability[0]`），需求核对当前值，奖励按数值增加 |
| `信赖` | `信赖_<adv编号>_<数值>` | 对应角色的信赖度，需求核对当前值，奖励按数值增加 |
| `攻略` | `攻略_<adv编号>_<程度>` | 仅作需求判定，核对角色的攻略程度（`get_character_fall_level`，表头说明范围为 `0` 至 `4`） |
| `招募` | `招募_<adv编号>_<0或1>` | 仅作需求判定。填 `1` 时角色在编或处于离线状态均可通过。填 `0` 时显示为「未招募」，且不会阻止接取 |
| `追捕` | `追捕_<角色id>_1` | 仅由 `create_capture_fugitive_commission` 在生成临时追捕委托时写入，作者不要手写。编号为逃犯的角色 id，完成时若有空闲关押宿舍则收押该逃犯 |

使用以下五类前缀时需特别注意边界行为：

- **`c` 项的数值与离线判定**：需求侧除 `1` 外均按禁止出勤处理。当数值为 `0` 且该干员未入队时需求通过，入队则失败。若填写大于 `1` 的正整数，干员未入队时当前值 `0` 仍小于需求值，需求永远无法通过，因此需求侧建议仅使用 `0` 或 `1`。当 `type` 为 `角色` 时，`c_` 项须放在 `demand` 第一项。奖励侧与 `招募` 项共同使用的「离线状态」指 `handle_normal_7` 返回 `0` 的情形，包括装袋搬走、外勤中、婴儿、幼女、他国外交访问中与逃跑中。
- **`m` 项对特殊委托的影响**：`m_<委托id>_0` 每次调用只清除一项标记，且先检查不可进行名单再检查已完成名单。若一条 `special` 非 `0` 的特殊委托同时处于不可进行名单与已完成名单中，单次 `m_<委托id>_0` 只会移除不可进行标记，该委托仍会因保留已完成标记而在非调试模式下继续隐藏。
- **`特产` 项的回退与适用范围**：`特产_0_<数量>` 会查找 `data/csv/Resource.csv` 中 `specialty` 列等于罗德岛当前所在国家编号的第一项资源（奖励在委托完成时按当时的所在国家判定）。加载资源时，只有 `specialty` 列非 `0` 的资源会进入按国家索引的特产表，因此国家 `0`（罗德岛）不会进入该索引。若所在国家未配置特产，目标资源编号会回退为文本中的 `0`（即 `Resource.csv` 中编号 `000` 的资源「无」），当前库存按 `0` 处理。在此情况下，正数需求无法通过，奖励只会增加资源 `0` 而不会给出有效物品。请仅在 `country_id` 属于已配置特产的国家（当前为 `Birthplace.csv` 中编号 `1` 至 `20` 的国家）时使用 `特产_0_<数量>`。当前未配置特产的国家为 `0` 罗德岛、`21` 北地、`22` 焚风热土、`23` 喀兰、`24` 檀、`25` 瓦伊凡、`26` 无尽冰原、`999` 未知。通用委托（`country_id` 为 `-1`）应使用明确的 `r_<资源id>_<数量>`。
- **`声望` 项的 `0` 编号回退**：`声望_0_<百分值>` 会按罗德岛当前所在国家匹配首个顶层势力。若当前所在国家没有匹配的顶层势力（当前为国家编号 `0`、`21` 至 `26` 与 `999`），当前声望值保持为 `0`。正数需求在这种情况下无法通过。奖励在无匹配势力时会记入势力 `0`（`Nation.csv` 中的「罗德岛」）。需要固定指向特定势力时，请直接填写具体势力编号，例如 `声望_171_<百分值>`（`171` 在 `Nation.csv` 中对应「炎」）。
- **`追捕` 项的来源**：`追捕` 委托仅由游戏运行时调用 `create_capture_fugitive_commission` 生成，不作为静态 CSV 编写内容。

## 从剧情到委托链

1. **拆分剧情节点**：按剧情先后顺序将章节拆分为若干关键节点，每个节点对应一条外勤委托。
2. **分配编号与标记**：查看 `data/csv/Commission.csv`，避开已占用号段和 `10001` 及以上的临时委托号段，为整条剧情链选取一段连续的未用 `cid`。剧情类委托按现有惯例将 `type` 设为 `支线`，并将 `special` 设为 `1`。
3. **串联前置顺序**：链上第一条委托的 `related_id` 填 `-1`，后续每条委托填前一条的 `cid`。非调试模式下，前置委托尚未完成时，后续委托会保持隐藏。
4. **配置分支关闭**：若剧情在某一节点出现二选一分支，让两条分支委托填写相同的 `related_id`，并在各自的 `reward` 中写入 `m_<另一条委托cid>_-1` 关闭未选分支（现有数据中 `155` 与 `156` 即共用前置 `54`，并分别通过 `m_56_-1` 与 `m_55_-1` 在奖励侧关闭对应委托）。
5. **匹配需求与奖励**：按节点行动内容搭配能力需求与对应经验奖励，战斗用 `a_42`（战斗技能）配 `e_81`（战斗经验），医疗用 `a_46`（医术技能）配 `e_88`（医疗经验），制造用 `a_48`（制造技能）配 `e_90`（制造经验），指挥用 `a_41`（指挥技能）配 `e_87`（指挥经验），交涉用 `a_40`（话术技能）配 `e_80`（对话经验），调查研究用 `a_45`（学识技能）配 `e_82`（学识经验），并按需要搭配 `r_` 或 `声望_` 项。

```text
2601,商队护送与伤员救治,-1,2,支线,2,2,a_42_3&a_46_2,e_81_10&e_88_10&r_1_500,-1,1,一支途经荒野山道的补给商队在夜间遭遇盗匪伏击，多名随行护卫与车夫在突围过程中负伤，目前商队被迫停留在临时营地等待外援协助撤离。\n请派遣具备战斗与医术能力的小队前往指定路段，先驱散周边游荡的袭击者并稳固防线，再为现场伤员完成清创包扎，确保整支商队安全抵达下一处城镇。
```

上例使用当前未占用的示例编号 `2601`（实际编写前须重新核对 `Commission.csv`），表示一条无前置、等级 `2` 的通用支线特殊委托，需派遣 `2` 人、基础耗时 `2` 天（载具总运载量至少为 `2`），要求派遣队伍经装备修正后的战斗技能之和达到 `3` 且医术技能之和达到 `2`，完成后向每名派遣队员发放 `10` 点战斗经验与 `10` 点医疗经验，并向仓库增加 `500` 龙门币（资源编号 `1`）。

## 描述规范

代码解析层面，面板在展示 `description` 时会把字面 `\n` 替换为换行符。配置构建脚本通过 Python 标准库 `csv.DictReader` 读取 `data/csv/Commission.csv`，运行时 `create_temp_commission` 则以未加引号的普通逗号拼接并追加写入新行。

以下文本风格要求属于作者编写约定，并非代码强制校验：

- 剧情类委托的 `description` 建议用 2 至 4 句话概括行动目标与关键经过，每句不少于 50 个中文字符，风格与现有支线委托保持一致。
- 需要分段换行时请写成字面 `\n`。
- 描述正文中的逗号请统一使用中文逗号 `，`，不要使用英文逗号 `,`，以免破坏未加引号行的 CSV 分列。

## 检查与构建

- 写入 `data/csv/Commission.csv` 后，核对每条新增行均为 12 列、`cid` 无重复且未占用 `10001` 及以上号段、`related_id` 为 `-1` 或已存在的 `cid`、`demand` 与 `reward` 前缀合法且数值均为整数、同一资源编号在 `demand` 里只写一项（例如把 `r_22_5&r_22_5` 合并为 `r_22_10`）、字段内无多余空格。
- 在仓库根目录运行 `python buildconfig.py` 重新生成配置。`buildconfig.py` 遇到缺列或类型转换失败时不会中止退出，而是打印 `Error: 文件 … 出现缺失行` 或 `Error processing row: …` 信息。运行结束后请检查终端输出，确认没有 `Error` 行。
- 游戏启动时 `game.py` 会导入 `auto_build_config` 对 `data/` 执行增量构建。必要时可启动游戏，在外勤委托面板中检查条目可见性、需求判定与描述换行效果。
