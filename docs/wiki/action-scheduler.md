# 行动调度设计契约

本页记录行动调度器的设计与实现。游戏通过 `Script/Modules/game_actions.py` 接入队列，旧 AI 与结算函数保留在原目录。

## 两个深模块

新入口位于 `Script/Modules/`。scheduler 管理时间、队列和执行顺序；npc_ai 根据角色和世界状态返回下一步 Action。旧 AI 留在原目录，由新入口调用，需求链和意图状态继续保存在角色数据中。强制行动直接提交调度器。

Action 表示一次具体行动，包含动作编号、目标、时长和必要参数；执行者和计划开始时间属于待办。现有 Behavior 表示当前行动的执行状态，其字段与原有收尾逻辑保持不变。若必须改变，先向用户报告。不批量移动旧文件。

## 队列与时间

一个优先队列。每个参与的 NPC 在本次任务完成后恰有一条待办；执行期间，刚取出的任务代表该角色。待办内容是具体行动、NPC 自主选择占位符或玩家输入占位符。

submit 要求角色没有待办；replace 明确替换角色待办。立即后续优先于普通任务，真实时刻仍是当前时间。普通任务按开始时间排序；同刻玩家输入优先于 NPC；其余并列按提交顺序。

取出任务后，将全局时间设为其开始时刻。AI 占位符在此刻询问 AI 并执行返回行动。当前结算返回后才执行后续，所有动作结算经调度器，禁止结算递归。若动作未提交后续，调度器在开始时间加时长处安排下一次 AI 或玩家输入。

UI 获取玩家指令后提交行动，调用 advance_until_input；取出玩家输入占位符时返回 UI。调度器不获取玩家输入。

## 动作效果

原子行动在开始时结算全部效果，占用其声明的时长。持续休息、睡眠拆成至多 30 分钟的原子片段；每段开始结算完整片段，结束时决定是否继续。中途被迫切换不扣回已结算效果。延续片段不重复入睡准备、首次台词或一次性效果。

玩家睡眠延续遵循玩家的睡眠计划与醒来条件，不走 NPC AI。玩家睡眠一次性结算在首次入睡时执行一次。公共按时间计算的恢复等沿用原公式，由公共执行入口传入该次完整时间区间，避免重复结算。

双人行动在主体身上结算一次。另一方安排带目标的等待行动，每 5 分钟检查主体 Behavior 类型及交互目标是否仍匹配自己；匹配则继续等待，否则恢复 AI。暂不添加行动实例 ID。

## 全局规则

时停期间暂停 NPC 自主与等待任务，保留其待办时刻；处理玩家及其直接触发的必要效果，沿用时停时间语义。第一次处理新日期的任务之前执行跨日结算。

新建或读档时必须正确建立队列，不能重复执行已结算的行动。所有原有递归路径需逐项确认强制后续和后续依赖的先后顺序。

## 修改与验收约束

修改集中在公共入口、递归调用点及持续动作适配，避免逐个重写普通动作。Behavior 收尾接入位置以实际代码审查为准。

实现以最新 upstream 主分支为基线，使用 meower-z 账号，向 meower-z/erArk-fork 的 main 提交内部 PR。多名 Astra、Fable 对整体进行批判性审查；每个变动函数分别由 Sonnet、Luna 提出简化建议，实施者判断采纳。验收覆盖时序交错、强制后续、占位符替换、输入优先、休息睡眠延续、双人等待、跨日、时停和读档。

## 实现入口

- `scheduler.py`：`Task(actor, at, item, immediate=False)`；`submit(task)` 新增，`replace(task)` 替换，`pending(actor)` 查询；`advance_until_input()` 返回玩家输入待办。内部使被替换的旧堆条目失效。
- `action.py`：`Action.from_character()` 接收旧 AI 或指令已准备的行为；`apply()` 在执行时安装旧 Behavior。`continued` 标识静默延续；`wait_on` 保存双人等待条件；`after` 与 `followups` 保存必须顺序执行的后续。
- `npc_ai.py`：`choose_next(actor, now)` 返回 Action；旧检查已提交强制行动时返回 None。睡眠、休息的继续判断在片段边界进行。
- `game_actions.py`：公共桥接负责旧效果、收尾和特殊行动链。`submit_current()` 提交强制后续，`wait_on()` 替换参与者待办，`reset_character()` 清除上下线角色的旧计划。旧 UI 通过 `update.game_update_flow()` 进入 `Runtime.advance()`。

玩家输入返回之前收尾玩家当前行为；NPC 选择下一步或被强制替换时收尾。保留 Behavior 的字段定义与旧收尾函数。当前行为的快照用于收尾，实时交互目标不随快照回退。

首次读入没有调度器的旧存档时，从当前行为建立剩余时间片段，不重放主效果。新存档保存队列；需要角色编号迁移的存档重建队列。游戏日历仅包含四个季月，时间区间计算使用 `game_time.elapsed_minutes()`，避免跨季被当成数月。

## 验证范围

`python -m unittest discover -s tests -v` 检查队列顺序、同刻输入优先、强制链、待办替换、恢复片段、睡眠一次性效果、双人等待、读档、上下线、跨日和时停。测试以真实队列和接入层配合外围替身运行；完整游戏流程仍需使用实际存档及界面验证。
