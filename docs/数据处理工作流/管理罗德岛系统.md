# 管理罗德岛系统

## 界面入口

管理罗德岛系统包含两个界面。主界面为「管理罗德岛」（`Manage_Basement_Panel(width)`），提供「罗德岛资源总览」「各部门工作概况」与「全干员一览」三个页签。岗位调整界面为「调整干员工作岗位」（`Change_Npc_Work_Panel`），由公开函数 `change_npc_work_out(width, target_work_type_id=None)` 打开，十个其他系统面板通过该函数高亮并预展开指定岗位。

## 模块职责

- `Script/UI/Panel/manage_basement_panel.py`：主面板与岗位调整界面的绘制壳层与输入循环，提供 `Manage_Basement_Panel`、`Change_Npc_Work_Panel` 与 `change_npc_work_out`。
- `Script/UI/Panel/basement_roster_panel.py`：绘制「全干员一览」页签并维护筛选、排序、分页与分类状态（`RosterTab`、`draw_text`、`draw_button`、`pass_func`）。
- `Script/Modules/gameplay_resolution/basement_overview_service.py`：基建总览查询，公开 `capacity`、`stock_rows`、`departments`、`staffing`、`income`、`staff_text`、`department_text` 与 `entry_notice`。
- `Script/Modules/gameplay_resolution/operator_list_service.py`：干员列表查询，公开 `ability_columns`、`sort_value`、`is_collected`、`visible_ids`、`page_of`、`fall_label`、`equipment_label`、`position_text`、`work_name` 与 `operator_ids`。
- `Script/Modules/gameplay_resolution/work_assignment_service.py`：岗位分组与指派服务，公开 `refresh_groups`、`current_work_text`、`work_options` 与 `assign_work`。

上述三个后端服务模块均不导入 `Script.UI` 与 `Script.Settle`。

## 状态读写

后端服务与面板通过 `Script/Modules/domains/` 领域接口读写内核状态，主要调用包括 `warehouse.capacity()`、`warehouse.stock()`、`warehouse.amount()`、`work.roster()`、`work.people_now()`、`work.warden()`、`work.set_warden()`、`facility.is_open()`、`facility.people_max()`、`economy.income()`、`maintenance.damage()`、`maintenance.places()`、`recruit.pending()`、`recruit.lines()`、`commission.ongoing()`、`commission.vehicles()`、`prison.prisoner_ids()`、`roster.active()`、`roster.count()`、`visitor.is_visitor()`、`identity.of()`、`chara_life.work_type`、`chara_life.dormitory`、`chara_profile.chara_setting`、`abilities.ability()`、`abilities.talent()`、`body_manage.clear()`、`relations`、`needs`、`hypnosis` 与 `activity`。

`basement.update_work_people()` 仅在 `refresh_groups()` 与 `assign_work()` 中调用，主面板本身不触发名册刷新。图书馆详情页中的读者人数在绘制时实时调用 `basement.library_reader_count()` 计算。

## 岗位判定与指派规则

`work_options(chara_id)` 按工作配置顺序计算每个岗位的开放与可选状态。

1. 先校验工作配置的 `need` 字段，非 `"无"` 时按 `&` 拆分后调用 `attr_calculation.judge_require`。
2. 再校验 `place` 对应的待开放设施是否已通过 `facility.is_open` 开放。
3. `tag == 2` 的特殊岗位按专属条件判定开放：岗位 `191`（监狱长）要求当前有在押囚犯且干员陷落等级为 3 或 4，岗位 `193`（性爱练习生）要求干员存在编号 30 至 39 中非零的身体管理训练项。
4. 岗位开放且 `tag` 为 0 或 2 时允许选中指派。开放但 `tag == 1` 的岗位以灰色文本展示并附未开放原因（如外交官）。未开放的岗位同样灰显原因。

`assign_work(chara_id, work_id)` 负责写入新岗位并同步副作用。干员离开 `193`（性爱练习生）时调用 `body_manage.clear` 清空编号 30 至 39 的训练项。在任监狱长离任时先将工作设为 0、调用 `Dormitory_System.common.restore_character_dormitory` 恢复原宿舍并调用 `work.set_warden(0)` 置零。写入新工作后，若目标为 `191`（监狱长），系统先将已有其他监狱长的工作设为 0 并恢复宿舍，再调用 `work.set_warden`、登记永久宿舍并将宿舍设为 `["关押", "休息室"]` 对应路径。最后调用 `basement.update_work_people()` 刷新全基地名册。
