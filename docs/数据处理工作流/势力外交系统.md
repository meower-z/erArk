# 势力外交系统

## 系统概述

势力外交系统是erArk游戏中的核心政治管理模块，允许玩家通过派遣外交官执行不同的外交方针来影响各势力的声望和地区的源石病感染率。该系统涉及多个数据层面的交互，包括势力管理、外交官分配、政策执行和周期性结算。

## 数据文件结构

### 1. CSV数据文件

#### Nation.csv (势力数据)
```csv
cid,name,country,leader,introduction
0,罗德岛,0,博士,致力于矿石病研究和感染者救治的国际性医疗机构
11,阿戈尔,1,待填写,地处深海的国家，对外相对封锁...
12,深海猎人,1,歌蕾蒂娅,隶属于深海国家阿戈尔的军事力量...
```
- **层级结构**：主要国家(country字段为正数) -> 附属势力(country字段指向主要国家)
- **特殊标识**：country=-1表示独立势力，country=0表示罗德岛相关

#### Birthplace.csv (国家地区数据)
```csv
cid,name,inmap,infect_rate
1,阿戈尔,1,5
4,哥伦比亚,1,45
6,卡兹戴尔,1,95
7,拉特兰,1,0
```
- **感染率**：各地区的初始源石病感染率(0-100%)
- **地图显示**：inmap字段控制是否在大地图中显示

#### Diplomatic_Policy.csv (外交政策)
```csv
cid,name,difficulty,need,info
1,在民间开展源石病治疗工作,1,无,小幅度降低当地的源石病感染率
2,设立和完善外勤办事处,2,无,小幅度提高地区声望
5,与势力领导人进行密切交流,5,无,大幅度提高势力声望和地区声望
```
- **难易度**：1-5级，限制可执行的政策
- **效果**：影响感染率或声望的具体数值在代码中定义

## 界面与外交服务

### 1. 外交服务 (`Script/Modules/gameplay_resolution/nation_diplomacy_service.py`)

本模块承接势力外交界面的全部数据查询、状态写入与读档修补逻辑。本模块不导入 `Script.UI` 与 `Script.Settle`，可在无界面进程中独立运行。

#### 查询与操作入口
- `list_nations(countries)`：按分页返回势力列表行数据（`NationRow`）。参数 `countries` 为 `True` 时列出各国家主势力，为 `False` 时列出国家编号为 `-1` 的其他势力。结果跳过国家编号为 `0` 的罗德岛自身势力与编号 `502` 的势力。
- `nation_detail(nation_id)`：返回势力详情（`NationDetail`），包含势力名称、保留两位小数的声望、所属国家保留三位小数的感染率（无记录时为 `0`）、国家特产资源名称与各附属势力的声望及等级。
- `posting(nation_id)`：返回所属国家在任外交官与外交方针展示数据（`Posting`），包含外交官信息、话术技能（`Ability.csv` 编号 `40`）名称、五倍能力修正效果百分比与当前外交方针名称。外交官空缺时返回 `None`。
- `candidates(nation_id)`：返回可选外交官列表（`Candidates`），从在编干员与该国在任外交官中筛选出身地等于所属国家或所属势力等于目标势力的干员。
- `assign_diplomat(character_id, nation_id)`：任免势力所属国家的外交官。若该国已有在任外交官，函数先清空其外交工作、驻在国标记与外交官岗位。若 `handle_premise.handle_normal_7` 判定旧外交官仍离线，函数调用 `roster_lifecycle_service.chara_on_line` 将其召回在编名单。解除后函数为旧外交官写入解除二段行为并执行 `talk.must_show_talk_check`。当 `character_id` 为 `0` 或等于原在任外交官编号时，函数跳过新任命并直接返回 `None`。否则函数为新外交官设置工作类型 `131`、外交岗位与驻在国标记，写入任命二段行为并执行 `talk.must_show_talk_check`。若目标国家不是罗德岛当前所在国家，函数调用 `roster_lifecycle_service.chara_off_line` 将新外交官置为离线。完成新任命后函数返回任命摘要（`Appointment`）。
- `policies(nation_id)`：返回可选外交方针元组（`Policy`），仅保留难度不超过访客区（设施编号 `13`）等级且不超过在任外交官话术技能（编号 `40`）等级的方针，并标记当前生效方针。
- `set_policy(nation_id, policy_id)`：将势力所属国家当前的外交方针设为 `policy_id`。

#### 读档修补
- `update_nation_data()`：由 `@reset.repair` 登记，仅在读档重置流程的 `repairs` 步骤中执行。当全部势力声望与全部国家感染率均为 `0` 时，函数将各国感染率重置为 `Birthplace.csv` 中的初始值。检查过程中缺失的声望与感染率记录按 `0` 处理。

### 2. 界面面板 (`Script/UI/Panel/nation_diplomacy_panel.py`)

`Nation_Diplomacy_Panel` 负责势力外交界面的绘制与用户输入。游戏状态读写全部委托给 `nation_diplomacy_service`。面板在模块顶层导入该服务，从而在游戏启动加载界面流程时完成 `update_nation_data` 的登记。

- `draw()`：绘制势力外交主界面，支持在「国家及附属势力」与「其他势力」页签间切换。函数按 `list_nations()` 的结果绘制各势力行按钮，点击后进入 `nation_info()`。
- `change_panel(building_type)`：切换当前显示的页签名称。
- `nation_info(nation_id)`：按 `nation_detail()` 绘制势力名称、声望、特产资源与附属势力。处于「国家及附属势力」页签时，函数同时显示感染率并调用 `draw_posting()`。
- `draw_posting(nation_id, return_list)`：按 `posting()` 绘制在任外交官、当前外交方针与「【调整负责外交官】」按钮。已任命外交官时，函数同时绘制「【调整外交方针】」按钮。
- `adjust_NPC(nation_id)`：按 `candidates()` 绘制候选干员按钮，并用高亮样式标出当前在任外交官。选中干员后调用 `sure_NPC()`。
- `sure_NPC(character_id, nation_id)`：调用 `assign_diplomat()` 执行外交官任免。产生新任命时，函数按任命国家是否为罗德岛当前所在国家绘制对应的等待提示。
- `adjust_diplomatic_policy(nation_id)`：按 `policies()` 绘制可选方针按钮，并用高亮样式标出当前生效方针。选中方针后直接调用 `set_policy()`。

## 周期结算服务 (`Script/Modules/gameplay_resolution/diplomacy_service.py`)

### `judge_diplomatic_policy()` - 外交方针周结算
- **结算周期**：每周执行一次外交方针效果，跳过外交官或方针为 0 的国家
- **能力计算**：基于外交官的外交能力（`ability[40]`）计算正的能力修正与随机因子（`uniform(-6 + ability[40], 6 + ability[40]) / 10`，能力低于 6 时随机因子可为负）
- **效果应用**（增减方向随随机因子正负而定）：
  - 政策 1、4：按倍率 0.01 与 0.05 调整对应国家感染率（随机因子为正时降低，为负时升高）
  - 政策 2、3、5：按倍率 0.1、0.1、0.3 调整主势力声望，附属势力按 0.5、3、1 倍同步调整（随机因子为正时提高，为负时降低）
- **经验奖励**：按方针难易度为外交官结算对话经验（80）与学识经验（82）
- **结果输出**：经 `ui_hooks.emit_delta` 发出本周全势力声望总变化项与摘要文本（不输出感染率总变化）

### `settle_all_country_infection_rate()` - 各国感染率周结算
- **结算逻辑**：按每周治疗加权量更新大地图各国（除国家 7 拉特兰外）的感染率与病人系数，并将国家 7 的病人系数设为 0.1
- **收尾与输出**：清零每周治疗加权量并更新上周感染率总和，经 `ui_hooks.emit_delta` 发出感染率统计报告文本与两条变化项（各国平均、当前所在国家）

## 系统集成关系

### 1. 与结算系统的集成 (`Script/Settle/past_day_settle.py`)
- **调用点**：`update_new_day()` 调用 `diplomacy_service.judge_diplomatic_policy()` 与 `diplomacy_service.settle_all_country_infection_rate()`
- **触发条件**：`game_time.now().weekday() == 6`（每周一次）
- **数据持久化**：结算结果经 `Script/Modules/domains/country.py` 保存到全局键 `world.country` 中

### 2. 与能力计算系统的集成 (`Script/Design/attr_calculation.py`)
- **国家数据初始化**：`get_country_reset()`函数
- **声望等级转换**：`get_reputation_level()`函数
- **能力效果计算**：`get_ability_adjust()`函数

### 3. 与外勤委托系统的集成 (`Script/UI/Panel/field_commission_panel.py`)
- **声望奖励**：完成特定国家的委托可获得对应势力声望
- **委托过滤**：根据外交方针优先显示特定类型的委托
- **地区关系**：外交关系影响委托的可用性和奖励

### 4. 与角色系统的集成
- **出身地绑定**：character.relationship.birthplace字段
- **势力归属**：character.relationship.nation字段
- **工作分配**：character.work.work_type = 131表示外交官
- **特殊标记**：character.sp_flag.in_diplomatic_visit标记外派状态

## 重要算法逻辑

### 1. 声望计算算法
```python
# 基础公式
ability_adjust = attr_calculation.get_ability_adjust(diplomat_ability_level)
random_factor = random.uniform(-6 + ability_level, 6 + ability_level) / 10
final_effect = base_effect * ability_adjust * random_factor

# 附属势力声望传播
main_nation_reputation_change = final_effect
subordinate_reputation_change = final_effect * multiplier  # 0.5或3.0根据政策
```

### 2. 感染率计算算法
```python
# 感染率降低计算
down_rate = policy_base_rate * ability_adjust * random_factor
new_infection_rate = current_rate - down_rate
# 政策1: base_rate = 0.01, 政策4: base_rate = 0.05
```

### 3. 外交官匹配算法
```python
# 外交官候选条件
def is_diplomat_candidate(character_data, target_country_id, target_nation_id):
    return (character_data.relationship.birthplace == target_country_id or 
            character_data.relationship.nation == target_nation_id)
```

## 系统特点与设计思路

### 1. 层级化势力系统
- **主要国家**：如维多利亚、哥伦比亚等，拥有多个附属势力
- **附属势力**：如深海猎人(属于阿戈尔)，声望变化会传播到主要国家
- **独立势力**：不属于任何国家的特殊组织

### 2. 能力驱动的效果系统
- **外交官能力**：ability[40]外交能力直接影响政策效果
- **随机性引入**：避免固定数值，增加游戏的不确定性
- **等级限制**：高级政策需要高能力外交官和高级设施

### 3. 长期发展机制
- **周期性结算**：外交效果不是立即生效，而是持续产生影响
- **经验成长**：外交官在执行任务中获得经验，形成正循环
- **状态持久化**：外交关系和感染率变化会永久保存

### 4. 地理位置相关性
- **本地 vs 外派**：罗德岛位置影响外交官的工作状态
- **地区特产**：不同国家有不同的资源特色
- **移动影响**：罗德岛移动会影响外交官的在线状态

## 扩展性设计

### 1. 可扩展的政策系统
- 新增外交政策只需在CSV中添加数据，代码中添加对应的effect处理
- 政策效果可以灵活调整，支持复杂的条件判断

### 2. 动态的势力关系
- 势力间的关系可以通过配置文件灵活定义
- 支持势力归属关系的动态变化

### 3. 模块化的界面系统
- 外交界面独立于其他系统，便于维护和扩展
- 支持不同类型的外交操作和显示模式

## 性能考虑

### 1. 数据缓存机制
- 配置数据在游戏启动时一次性加载，避免重复IO操作
- 游戏状态数据使用内存缓存，提高访问效率

### 2. 计算优化
- 外交效果计算只在周期结算时进行，避免实时计算开销
- 界面显示数据按需计算，减少不必要的处理

### 3. 存储优化
- 只存储变化的数据，初始数据通过配置文件恢复
- 使用字典结构提高数据查找效率

这个势力外交系统体现了erArk游戏在政治模拟方面的深度设计，通过多层次的数据结构、复杂的计算逻辑和丰富的交互界面，为玩家提供了一个真实而有趣的外交管理体验。
