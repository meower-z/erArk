# 资源交易系统

## 系统概述

资源交易系统负责罗德岛的物资买卖、自动贸易和市场波动。主界面与资源选择的绘制和输入位于 `Script/UI/Panel/resource_exchange_panel.py`，交易员管理、主交易员任命与自动交易设置三个子界面位于 `Script/UI/Panel/trade_setting_panel.py`。报价快照、数量钳制、交易文案、列表过滤与交易员及自动交易写入规则位于 `Script/Modules/gameplay_resolution/resource_exchange_service.py`。价格计算、供需调节、交易执行与每日自动交易位于 `Script/Modules/gameplay_resolution/trade_service.py`。

系统依托贸易区的"资源交易员"工作（工作类型 111）运作：干员被安排为资源交易员后自动进入交易员列表，各资源类型可从中任命主交易员，任命后才能配置并执行该类型资源的自动交易。交易面板采用分区式布局，交易数量为带符号语义（正数=买入，负数=卖出）。每日 0 点结算时供需系数按均值回归模型自然波动，并随即触发一次"盘后自动交易"。

## 关键数据结构

### 1. Resource 配置 (config_def.py)
```python
class Resource:
    cid: int        # 资源id
    name: str       # 资源名字
    type: str       # 资源类型
    price: int      # 资源价格
    cant_buy: int   # 是否无法购买
    specialty: int  # 地区特产(对应出身地cid)
    info: str       # 介绍信息
```
资源类型分为：货币（001~004：龙门币/合成玉/至纯源石/粉红凭证）、材料（011~016）、药剂（021~024）、乳制品（031~036）、香水（041~044）、基建（051~055）、特产（101 起，按 `specialty` 对应国家分组）。加载时除 `config_resouce` 外还会构建 `config_resouce_data_of_nation`（`game_config.py`，将 `specialty != 0` 的资源按国家 id 归类，供特产判定使用）。

### 2. 贸易数据

资源库存、已用的仓储空间扩展模块数与仓库容量归 `Script/Modules/domains/warehouse.py` 管理，见下文「初始化与仓库容量」。
罗德岛所在的国家在 GameState 的全局键 `base.location` 里，用 `location.country()` 读。特产判定拿它比对资源的 `specialty`。
交易数据是内核状态的全局键，归 `Script/Modules/domains/economy.py` 所有：
```python
base.supply_demand   # 资源id: 供需系数，表里没有的资源按 1 算
base.traded_today    # 资源id: 今日买入卖出总量
base.main_traders    # 资源类型: 主交易员角色id，表里没有的类型为 0（空缺）
base.auto_trade      # 资源id: 自动交易设置，表里没有的资源读 DEFAULT_AUTO_TRADE
```
代码经 `economy` 的函数读写这些键，例如 `economy.supply_demand()`、`economy.main_trader(res_type)`、`economy.set_auto_trade(rid, setting)`。表的键在状态里存成字符串，读函数交出的资源 id 是 int。`base.traded_today` 归规则所有，只能经 `economy.add_traded()` 与 `economy.set_traded()` 改。

交易员名单不存。`economy.trade_operator_ids()` 每次从岗位名册 `work.roster(111)` 读出它。

`base.auto_trade` 以**资源 id**为键（注意不是资源类型），一项设置有 `buy_on`、`buy_stock`、`buy_price_percent`、`sell_on`、`sell_stock`、`sell_price_percent` 六个键。`economy.auto_trade(rid)` 对没有设置过的资源交出 `DEFAULT_AUTO_TRADE`（两个百分比为 100，其余为 0/False）。设置过的资源缺的键读 0。

### 3. 初始化与仓库容量
- 资源库存存在 GameState 的全局键 `base.stock`（资源 id 的字符串到库存），已用的仓储空间扩展模块数存在 `base.warehouse_modules`。两者都经 `Script/Modules/domains/warehouse.py` 读写：读用 `warehouse.stock()`、`warehouse.amount(id)` 与 `warehouse.extra_modules()`，写用 `warehouse.add(id, n)`、`warehouse.set(id, n)` 与 `warehouse.set_extra_modules(n)`。
- 新游戏与新周目由 `creator_character_flow.first_bonus_and_setting_updata()` 调 `warehouse.start(...)`，给每种配置资源记下库存 0，再换上开局库存。
- 新游戏时罗德岛在国家 17（`location.START`），没有 `base.location` 时读到这个值。主交易员与自动交易设置不预先填表，表里没有的项读上节的默认值。
- 仓库容量不存，用 `warehouse.capacity()` 读时算出：仓储区当前等级的效果值 + `warehouse.extra_modules()` × 200。仓储空间扩展模块（资源 055）由制造加工区产线生产后使用。
- 存档兼容：读版本 7 之前的存档时，`warehouse.adopt_old_save` 把罗德岛对象上的 `materials_resouce` 与 `used_extra_warehouse_capacity_module` 搬进 `base.stock` 与 `base.warehouse_modules`。之后 `save_handle.install_save` 给存档里缺的配置资源记下 0。版本 5 之前的存档把交易数据放在罗德岛对象上，读档时 `upgrade.adopt_economy()` 把它们写进内核状态，并从对象上删掉，交易员名单不搬。角色 id 重构脚本 `Script/Core/old_chara_to_new.py` 用 `economy.remap_traders()` 重映射主交易员。

## 价格与供需机制

价格由三个因素相乘（`get_resouce_price()`）：
1. **基础价格**：特产且身处其特产国家时，基础价直接乘 1.5；其他情况买入使用 `1.1 * base_price`，卖出使用 `0.9 * base_price`。
2. **供需系数**：`base.supply_demand` 里没有的资源按 1 算。交易后每满 50 单位触发一步 `_adjust_supply_demand_after_trade()`：买入推动系数上行（上限 **5.0**），卖出推动系数下行（下限 **0.1**）。当日累计交易量（`base.traded_today`）越大，买入端单步涨幅越大、卖出端单步跌幅越小。
3. **交易员话术加成**：`calculate_trade_multiplier()` 按主交易员与全部副交易员的 40 号能力（话术技能）等级计算，主、副分别提供每级 `0.5%` / `0.1%` 的线性加成；买入乘数下限 50%，卖出乘数上限 200%。

`get_resouce_price(resouce_id, buy_or_sell_flag, self_check=True)` 返回整数单价与相对基础价的波动百分比。`self_check` 参数用于安全约束的一次性递归：买入价不得低于卖出价、卖出价不得高于买入价（内部再调用一次自身并传 `self_check=False` 防止无限递归）。

> 配置与实现不一致：`Facility.csv` 中贸易区的描述写有"升级可以降低买入价格，提升卖出价格"，但 `get_resouce_price()` 实际并未读取贸易区设施等级，价格只由上述三因素构成。

## 交易执行流程

- `perform_trade(resouce_id, quantity, buy_flag)`：唯一的交易结算入口。买入时按剩余仓容与资金可负担量截断数量，卖出时按持有库存截断。成功后更新库存、龙门币（资源 1）、供需系数与今日交易量，返回实际成交信息 `{"quantity", "price", "total_price"}`，失败返回 `None`。
- `_adjust_supply_demand_after_trade()`：按每 50 单位一步调整供需系数（见上节）。
- `auto_trade_resources()`：每日自动交易（详见下节），仅在 `daily_supply_demand_fluctuation()` 末尾被调用，无其他外部调用点。

## 自动交易与交易员管理

### 交易员来源（工作 111）
- 交易员不在交易面板中直接添加，而是通过**工作分配**产生：干员的 `chara_life.work_type(cid)`（角色键 `life.work_type`）被设为 111（资源交易员）后，`basement.update_work_people()` 把它放进岗位名册 `work.roster(111)`，`economy.trade_operator_ids()` 从这里读出交易员名单。`update_work_people()` 每次执行都会调 `economy.drop_invalid_traders()`，把角色不存在、工作已变更等无效的主交易员改为 0。
- 面板中的 `[交易员增减]` 按钮实际调用 `manage_basement_panel.change_npc_work_out(width, [111])`，打开职业调整面板并高亮资源交易员一职。

### 主交易员任命
- `Resource_Exchange_Line_Panel.manage_trade_operator()` 委托 `trade_setting_panel.manage_traders()` 绘制交易员管理页。页面调用 `resource_exchange_service.roster()` 展示各资源类型的主交易员与其余副交易员的话术等级，并提供 `[任命]` 与 `[清空]`（调用 `resource_exchange_service.clear_main_trader()`）按钮。
- `trade_setting_panel.assign_main_trader()` 从 `resource_exchange_service.candidates()` 读取候选交易员，经通用 NPC 选择面板（`common_select_NPC`）选人，并由 `resource_exchange_service.toggle_main_trader()` 写入。再次选择当前主交易员时会将其清空为 0。
- 主交易员按**资源类型**任命（`base.main_traders`），只有已任命主交易员的类型才能配置并执行自动交易。

### 自动交易设置（auto_trade_setting）
- `Resource_Exchange_Line_Panel.auto_trade_setting()` 委托 `trade_setting_panel.auto_trade_setting()` 按**单个资源**绘制设置页。买入侧配置 `buy_on` 开关、`buy_stock` 目标库存与 `buy_price_percent` 触发价百分比（相对基础价），卖出侧配置 `sell_on`、`sell_stock` 与 `sell_price_percent`。
- 开关切换调用 `resource_exchange_service.toggle_auto_trade()`，数值调整与 `[重置]` 调用 `resource_exchange_service.adjust_auto_trade_value()`。数值下限为 0，百分比上限为 `PERCENT_CAP`（300%），仓库容量大于 0 时库存上限为 `warehouse.capacity()`，点击 `[重置]` 会直接写回 0。
- 界面提供 ±1/10/100/1000、±1%/5%/20% 快捷按钮与 0 点结算条件预览文本。

### 自动交易执行（auto_trade_resources）
- 前置条件：交易员名单（`economy.trade_operator_ids()`）非空。逐资源类型处理（跳过"无"和"货币"），且该类型必须已任命主交易员。
- **先自动卖出、后自动买入**（先卖出回笼资金，再执行买入）。
- 触发判定为百分比制，直接与 `get_resouce_price()` 返回的波动百分比比较：
  - 卖出：`sell_on` 开启、库存 > `sell_stock` 且 `当前卖出波动% + 100 ≥ sell_price_percent` 时，卖出至保留库存；
  - 买入：`buy_on` 开启、`buy_stock > 0`、资源可购买（`cant_buy == 0`）、库存 < `buy_stock` 且 `当前买入波动% + 100 ≤ buy_price_percent` 时，买入至目标库存。
- `auto_trade_resources()` 仅返回成交明细行列表而不绘制界面。有成交时由 `basement.update_base_resouce_newday()` 以 `○贸易部结算：` 为抬头绘制成交明细。

## 每日供需刷新

`daily_supply_demand_fluctuation()` 的完整触发链（每日 0 点跨日时）：

```
character_behavior.py（跨日） → past_day_settle.update_new_day()
  → basement.update_base_resouce_newday()
    → trade_service.daily_supply_demand_fluctuation()
      → 供需均值回归+随机波动 → 重置今日交易量 → auto_trade_resources() 返回成交明细
    → 有成交时由 basement 绘制「○贸易部结算：」提示
```

- 对除龙门币（资源 1）外的全部资源执行"均值回归 + 随机波动"的供需演化：偏离 1 越远回归越强（回归系数 0.05），随机波动基础 ±0.005 且偏离越大波动越大，结果下限 0.1。合成玉等其他货币类资源同样参与波动，只是不在交易面板中展示。
- 同时把除龙门币外每种资源的今日买卖量（`base.traded_today`）归零，随后自动触发一次 `auto_trade_resources()`，实现"每日盘后自动交易"。

## UI 面板交互

`Resource_Exchange_Line_Panel` 为主面板类（默认选中资源 011 普通药材）。每次重绘在 `draw()` 中调用 `resource_exchange_service.quote()` 生成 `Quote` 快照，再由四个区块方法绘制界面。

### 主界面（draw()）的四个区块
1. **【资产与库存】**（`_draw_assets()`）：展示当前龙门币、交易资源与 `[更改交易资源]` 按钮、库存与仓容（满仓时使用金色样式），以及自动交易摘要（未任命主交易员时提示且不显示 `[自动交易设置]` 按钮）。
2. **【交易员与倍率分析】**（`_draw_traders()`）：提供 `[交易员管理]` 按钮，展示交易种类、主交易员（空缺时使用警告样式）、副交易员人数与名单、各自基础加成以及综合倍率。
3. **【交易详情与预算】**（`_draw_budget()`）：展示当前交易数量、预计库存变化、买入价与卖出价（按交易方向高亮）、`Quote.total` 预计总价、`Quote.money_left` 交易后余额，以及资金不足或不可购买警示。
4. **【数量调节】**（`_draw_adjust()`）：最大卖出按钮调用 `settle_max_sell()`（委托 `resource_exchange_service.max_sell()`），最大买入按钮调用 `settle_max_buy()`（委托 `resource_exchange_service.max_buy()`，禁买或买价非正时保持原值），±1/10/100/1000 按钮调用 `settle_quantity()`（委托 `resource_exchange_service.step()`），重置按钮调用 `reset_quantity()`。当 `Quote.confirm` 为真时显示 `[确认买入]`（数量大于 0、资金足够且可购买）或 `[确认卖出]`（数量小于 0、库存足够且为非特产或身处产地）。

### 交易数量的符号语义
`quantity_of_resouce` **正数代表买入、负数代表卖出**。`execute_trade()` 调用 `resource_exchange_service.trade()`，后者在数量非零时按符号委托 `trade_service.perform_trade()` 并返回 `Deal` 结果，实际成交量与请求量不一致时附带实际成交提示，成交成功后由面板将 `quantity_of_resouce` 归零。`settle_quantity()` 通过 `resource_exchange_service.step()` 先按剩余仓容设上限、再按负库存设下限进行钳制。

### 资源选择（select_exchange_resouce()）
分类折叠列表浏览材料、药剂、乳制品、香水、基建与特产六类资源，货币类不展示。展开分类时调用 `resource_exchange_service.listings()` 获取 `Listing` 列表，非产地且库存为零的特产会被隐藏，每项展示存量、可购买时的买入价以及卖出价与波动百分比。

面板关闭时通过 `view.now_panel_id = constant.Panel.IN_SCENE` 切回场景界面。

`base.stock` 是全罗德岛共用的资源池，经 `Script/Modules/domains/warehouse.py` 读写。除交易系统外的主要读写方：

## 业务约束与注意事项

- 价格、供需、自动交易依赖 `warehouse`（全局键 `base.stock`）中的库存与资金，以及 `economy` 的交易数据。任何外部脚本改动库存/资金后应考虑对自动交易与供需的影响。
- 交易员能力使用角色 `ability[40]`（话术技能），缺失角色数据会被安全跳过。
- 自动买入需要资源可购买（`cant_buy == 0`），自动卖出默认允许；特产只能在产地买入，异地只能卖出。
- 每次交易数量以 50 为单位影响供需，调试时注意交易量级。
- 交易员名单不存，由 `economy.trade_operator_ids()` 从岗位名册读出，增删交易员要改干员的工作。主交易员的有效性由 `basement.update_work_people()` 调 `economy.drop_invalid_traders()` 统一校验。
