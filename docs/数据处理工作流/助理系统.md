# 助理系统说明文档

## 系统概述

助理系统是erArk游戏中的一个重要功能模块，允许玩家指定一名角色作为助理，该助理可以提供多种服务，包括跟随、问候、同居、辅佐等功能。系统通过CSV配置、Python代码逻辑和UI界面相结合，实现了完整的助理管理功能。

## 核心文件结构

### 主要代码文件

1. **`Script/Modules/gameplay_resolution/assistant_service.py`** - 无界面助理规则服务
2. **`Script/UI/Panel/assistant_panel.py`** - 助理面板UI界面
3. **`data/csv/AssistantServices.csv`** - 助理服务配置数据
4. **`Script/Config/game_config.py`** - 游戏配置加载器
5. **`Script/Config/config_def.py`** - 配置数据结构定义
6. **`Script/Core/game_type.py`** - 角色数据结构定义
7. **`Script/Design/attr_calculation.py`** - 属性计算和初始化
8. **`Script/Design/handle_premise.py`** - 前提条件处理
9. **`Script/Design/handle_npc_ai.py`** - NPC AI行为控制

### CSV数据文件

- **`data/csv/AssistantServices.csv`** - 定义了所有助理服务的配置信息

## 数据结构与流程

### 助理服务配置结构

#### CSV数据格式 (`AssistantServices.csv`)
```csv
cid,name,require,option
服务id,服务名,服务需求(用#分隔每个选项的需求)(F好感，X信任),各个选项
```

#### 具体服务配置
- **服务ID 2**: 跟随服务 - `否|是，智能跟随（在吃饭/上厕所/休息/睡觉等生理需求时会暂离，其他情况下跟随）`
- **服务ID 3**: 辅佐服务 - `否|是，在非跟随状态下，会自己在博士办公室里处理公务`
- **服务ID 4**: 送饭服务 - `否|帮忙买午饭|亲手做午饭|亲手做三餐`
- **服务ID 5**: 早安服务 - `否|早上叫起床|早安吻|早安咬`
- **服务ID 6**: 晚安服务 - `否|晚上催睡觉|晚安吻|晚安咬`
- **服务ID 7**: 同居服务 - `否|是`
- **服务ID 8**: 助攻服务 - `否|是，助理在场时对其他干员的指令实行值+50`
- **服务ID 9**: 性处理服务 - (未实装)
- **服务ID 10**: 每周轮换 - `否|是，每周一随机指定一名干员担任本周的助理`

## 系统工作流程

### 1. 数据加载流程

1. **CSV读取**: `buildconfig.py` 读取 `AssistantServices.csv`
2. **数据解析**: `game_config.py` 中的 `load_assistant_services()` 函数解析CSV数据
3. **配置存储**: 数据存储在 `config_assistant_services` 和 `config_assistant_services_option` 中
4. **角色初始化**: `attr_calculation.py` 中的 `get_assistant_services_zero()` 初始化角色助理服务

### 3. 服务配置流程

#### 面板按钮分发 (`Assistant_Panel.chose_button()`)
`Script/UI/Panel/assistant_panel.py` 中的 `Assistant_Panel.chose_button(service_cid)` 在编号为 0 时打开 `chose_assistant()`，将其余服务编号委托给 `assistant_service.cycle_service(service_cid)`。
```python
def chose_button(self, service_cid: int) -> None:
    if service_cid == 0:
        chose_assistant()
    else:
        assistant_service.cycle_service(service_cid)
```

#### 服务选项切换逻辑 (`cycle_service()`)
`Script/Modules/gameplay_resolution/assistant_service.py` 中的 `cycle_service(service_cid)` 读取 `game_config.config_assistant_services_option`，单独处理服务 2 的跟随步进，并在非调试模式解锁失败时输出提示、归零档位后直接返回。
```python
def cycle_service(service_cid: int) -> None:
    assistant_id = relations.assistant_character_id(0)
    if service_cid == 2:
        with relations.assistant_services.editing(assistant_id) as services:
            services[2] = not services.get(2, 0)
        follow = flags.get(assistant_id, "is_follow")
        flags.set(
            assistant_id,
            is_follow=0 if follow == 1 or follow > 4 else follow + 1,
        )
        return
    option_data = game_config.config_assistant_services_option[service_cid]
    options = option_data[0]
    with relations.assistant_services.editing(assistant_id) as services:
        level = services.setdefault(service_cid, 0)
    if level == len(options) - 1:
        relations.assistant_services.set_item(assistant_id, service_cid, 0)
    else:
        judge, reason = attr_calculation.judge_require(
            [option_data[1][level + 1]],
            assistant_id,
            hypnosis_replace_trust_flag=True,
        )
        if not judge and not modes.debug():
            ui_hooks.emit_notice(..., wait=True)
            relations.assistant_services.set_item(assistant_id, service_cid, 0)
            return
        relations.assistant_services.set_item(
            assistant_id, service_cid, level + 1
        )
    _settle_service_behaviors(assistant_id, service_cid, len(options))
```

#### 附带属性与同居宿舍结算 (`_settle_service_behaviors()`)
`Script/Modules/gameplay_resolution/assistant_service.py` 按 `OPTION_PREFIXES` 与 `SWITCH_PREFIXES` 同步二段行为，并在服务 7 开关变化时迁移或恢复宿舍。
```python
OPTION_PREFIXES = {
    4: "assistant_send_food_",
    5: "morning_service_",
    6: "night_service_",
}
SWITCH_PREFIXES = {
    3: "support_service_",
    7: "cohabitation_",
    8: "love_support_",
}


def _settle_service_behaviors(
    assistant_id: int, service_cid: int, option_len: int
) -> None:
    level = relations.assistant_services(assistant_id)[service_cid]
    if service_cid in OPTION_PREFIXES:
        prefix = OPTION_PREFIXES[service_cid]
        for index in range(option_len):
            second_behavior.character_get_second_behavior(
                assistant_id, f"{prefix}{index}", reset=True
            )
        second_behavior.character_get_second_behavior(
            assistant_id, f"{prefix}{level}"
        )
    elif service_cid in SWITCH_PREFIXES:
        prefix = SWITCH_PREFIXES[service_cid]
        second_behavior.character_get_second_behavior(
            assistant_id, f"{prefix}on", reset=True
        )
        second_behavior.character_get_second_behavior(
            assistant_id, f"{prefix}off", reset=True
        )
        second_behavior.character_get_second_behavior(
            assistant_id, f"{prefix}on" if level else f"{prefix}off"
        )
    if service_cid == 7:
        room = map_handle.get_map_system_path_str_for_list(COHABIT_ROOM)
        if level == 1:
            dormitory_common.register_permanent_dormitory(assistant_id)
            chara_life.dormitory.set(assistant_id, room)
        elif chara_life.dormitory(assistant_id) == room:
            dormitory_common.restore_character_dormitory(assistant_id)
```

#### 助理服务触发
通过二段行为标记 (`second_behavior`) 系统触发特定的助理服务：
- `chosen_as_assistant`: 被选为助理标记
- `not_as_assistant`: 非助理状态标记
- `assistant_send_food_X`: 送饭服务等级标记
- `morning_service_X`: 早安服务等级标记
- `night_service_X`: 晚安服务等级标记
- `support_service_on/off`: 辅佐服务开关标记
- `cohabitation_on/off`: 同居服务开关标记
- `love_support_on/off`: 助攻服务开关标记

## 系统特点与设计思路

### 1. 模块化设计
- **UI层**: `Script/UI/Panel/assistant_panel.py` 负责助理选择界面、面板绘制与早晚安时间交互
- **规则层**: `Script/Modules/gameplay_resolution/assistant_service.py` 负责无界面的候选筛选、任免替换、每周抽签、读档跟随修补与服务切换规则
- **数据层**: CSV配置文件提供基础数据
- **逻辑层**: 各种处理函数负责具体功能实现
- **AI集成**: 通过二段行为标记与NPC AI系统无缝集成

### 2. 灵活的配置系统
- **多选项支持**: 每个服务可以有多个等级选项
- **条件检查**: 支持基于好感度、信任度的解锁条件
- **动态配置**: 运行时可以随时调整服务配置

### 3. 状态管理
- **角色状态同步**: 助理的跟随、宿舍等状态与游戏世界同步
- **行为标记系统**: 通过二段行为标记触发相应的AI行为
- **状态持久化**: 助理配置通过存档系统持久化保存

### 4. 用户体验
- **直观界面**: 清晰的服务选项展示和状态反馈
- **智能提示**: 解锁条件不满足时提供明确的失败原因
- **时间定制**: 支持精确的时间设置（早安/晚安服务）

### 5. 扩展性
- **新服务添加**: 通过修改CSV文件和添加相应处理逻辑可以轻松添加新服务
- **AI行为扩展**: 通过二段行为标记系统可以轻松扩展AI行为
- **UI组件复用**: 使用通用的选择面板组件，便于维护和扩展

## 关键交互点

### 1. 与角色系统的交互
- 角色的基础属性（好感度、信任度）影响服务解锁
- 角色的特殊状态（异常、监禁等）影响助理候选资格
- 角色的位置信息用于跟随和同居功能

### 2. 与时间系统的交互
- 早安/晚安服务依赖游戏时间系统
- 每周轮换功能与日期系统集成

### 3. 与AI系统的交互
- 通过二段行为标记触发特定AI行为
- 跟随状态直接影响NPC的行为决策
- 助理服务与NPC日常行为相集成

### 4. 与地图系统的交互
- 同居服务涉及角色宿舍位置的变更
- 跟随功能依赖地图系统的位置追踪

### 5. 与存档系统的交互
- 助理配置和状态通过存档系统持久化
- 支持游戏重启后状态恢复

## 总结

助理系统是erArk游戏中一个设计精良的功能模块，通过CSV配置、Python逻辑处理、UI界面展示和AI行为集成，提供了完整的助理管理功能。系统具有良好的模块化设计、灵活的配置机制、清晰的状态管理和良好的扩展性，为玩家提供了丰富的助理互动体验。
