# 助理系统说明文档

## 系统概述

助理系统是erArk游戏中的一个重要功能模块，允许玩家指定一名角色作为助理，该助理可以提供多种服务，包括跟随、问候、同居、辅佐等功能。系统通过CSV配置、Python代码逻辑和UI界面相结合，实现了完整的助理管理功能。

## 核心文件结构

### 主要代码文件

1. **`Script/UI/Panel/assistant_panel.py`** - 助理选择与服务调整界面面板（绘制、输入交互与早晚安时间设置）
2. **`Script/Modules/gameplay_resolution/assistant_service.py`** - 无界面依赖的助理业务服务（候选筛选、任免替换、每周轮换、读档跟随状态修补与服务档位切换）
3. **`data/csv/AssistantServices.csv`** - 助理服务配置数据
4. **`Script/Config/game_config.py`** - 游戏配置加载器
5. **`Script/Config/config_def.py`** - 配置数据结构定义
6. **`Script/Core/game_type.py`** - 角色数据结构定义
7. **`Script/Design/attr_calculation.py`** - 属性计算和初始化
8. **`Script/Design/handle_premise.py`** - 前提条件处理
9. **`Script/Design/handle_npc_ai.py`** - NPC AI行为控制

### CSV数据文件

- **`data/csv/AssistantServices.csv`** - 定义了所有助理服务的配置信息

## 数据结构与流程

### 助理服务配置结构

#### CSV数据格式 (`AssistantServices.csv`)
```csv
cid,name,require,option
服务id,服务名,服务需求(用#分隔每个选项的需求)(F好感，X信任),各个选项
```

#### 具体服务配置
- **服务ID 2**: 跟随服务 - `否|是，智能跟随（在吃饭/上厕所/休息/睡觉等生理需求时会暂离，其他情况下跟随）`
- **服务ID 3**: 辅佐服务 - `否|是，在非跟随状态下，会自己在博士办公室里处理公务`
- **服务ID 4**: 送饭服务 - `否|帮忙买午饭|亲手做午饭|亲手做三餐`
- **服务ID 5**: 早安服务 - `否|早上叫起床|早安吻|早安咬`
- **服务ID 6**: 晚安服务 - `否|晚上催睡觉|晚安吻|晚安咬`
- **服务ID 7**: 同居服务 - `否|是`
- **服务ID 8**: 助攻服务 - `否|是，助理在场时对其他干员的指令实行值+50`
- **服务ID 9**: 性处理服务 - (未实装)
- **服务ID 10**: 每周轮换 - `否|是，每周一随机指定一名干员担任本周的助理`

## 系统工作流程

### 1. 数据加载流程

1. **CSV读取**: `buildconfig.py` 读取 `AssistantServices.csv`
2. **数据解析**: `game_config.py` 中的 `load_assistant_services()` 函数解析CSV数据
3. **配置存储**: 数据存储在 `config_assistant_services` 和 `config_assistant_services_option` 中
4. **角色初始化**: `attr_calculation.py` 中的 `get_assistant_services_zero()` 初始化角色助理服务

### 2. 助理选择流程

助理选择与替换的核心业务规则位于 `Script/Modules/gameplay_resolution/assistant_service.py`。该模块通过 `ui_hooks` 发送分隔线与提示文本，在 Tk 界面中由 `Script/Modules/tk_ui/callbacks.py` 承接绘制，未登记回调时不执行绘制。

#### 候选角色筛选 (`assistant_service.get_assistant_candidates()`)
`get_assistant_candidates()` 按角色编号升序遍历在编名单 `roster.active_sorted()`，并返回可担任助理的角色编号列表。筛选排除四类角色：

- 玩家角色 `0`
- 处于 2 或 7 类异常状态（AI 停止或离线，由 `handle_premise.handle_unnormal_27` 判定）的角色
- 当前监狱长（`work.warden()`）
- 访客（`visitor.is_visitor` 为真）

`assistant_panel.chose_assistant()` 调用该函数生成候选分页列表，并将每个候选按钮绑定到 `assistant_service.assistant_replace`。

#### 助理替换流程 (`assistant_service.assistant_replace(new_assistant_id)`)
`assistant_replace(new_assistant_id)` 按以下顺序完成任免与替换：

1. **清理当前助理**：若 `relations.assistant_character_id(0)` 非 `0`，函数先将当前助理的 `is_follow` 设为 `0`。若当前助理住在同居房间（`COHABIT_ROOM = ["中枢", "博士房间"]` 经 `map_handle.get_map_system_path_str_for_list` 拼接后的路径），函数调用 `dormitory_common.restore_character_dormitory` 恢复其宿舍。随后函数将当前助理的 `assistant_services` 重置为 `attr_calculation.get_assistant_services_zero()`。即便目标角色随后因异常状态被拒绝，上述清理仍会执行。
2. **输出分隔线与分支处理**：函数调用 `ui_hooks.emit_divider("-")`，再按目标角色执行对应分支。
   - **目标等于当前助理**：将 `relations.assistant_character_id(0)` 置为 `0`，解除助理职务。
   - **目标处于 2 或 7 类异常状态**：写入拒绝提示，保持玩家当前助理编号不变，并跳过后续卸任二段行为与卸任提示。
   - **其余情况**：将 `relations.assistant_character_id(0)` 设为 `new_assistant_id`，将其 `is_follow` 设为 `1`、服务 2（跟随服务）设为 `1`，重置 `not_as_assistant`、设置 `chosen_as_assistant` 并写入任命提示。
3. **卸任结算与输出提示**：若调用前存在助理且未进入拒绝分支，函数对 `new_assistant_id` 重置 `chosen_as_assistant`，为卸任角色设置 `not_as_assistant` 并追加卸任提示。最后函数调用 `ui_hooks.emit_notice(info_text, wait=True, use_text_width=True)` 输出合并后的提示文本。

#### 每周随机轮换与读档修补
- **每周轮换**：每日结算 `Script/Settle/past_day_settle.py` 的 `update_new_day()` 在周一且 `handle_premise.handle_pl_assistant_change_every_week_on(0)` 为真时，调用 `assistant_service.select_random_assistant()`。该函数从 `get_assistant_candidates()` 中随机抽取一名角色，经 `ui_hooks.emit_notice(..., wait=True, use_text_width=True)` 输出抽签提示后再调用 `assistant_replace`。
- **读档修补**：`assistant_service.repair_follow_flag()` 通过 `@reset.repair` 注册为读档修补钩子。读档时函数遍历身份表中全部角色，仅将 `is_follow > 4` 的标记归零，小于等于 `4`（含负数）的取值保持不变。

### 3. 服务配置流程

#### 服务选项切换逻辑 (`Assistant_Panel.chose_button` 与 `assistant_service.cycle_service`)
主面板按钮回调 `Assistant_Panel.chose_button(service_cid)` 接收单个参数 `service_cid`。`service_cid` 为 `0` 时调用 `chose_assistant()` 打开助理选择界面，非 `0` 时调用 `assistant_service.cycle_service(service_cid)` 执行档位切换。

`cycle_service(service_cid)` 对服务 2（跟随服务）与其他服务分别处理：

- **服务 2（跟随服务）**：将 `assistant_services[2]` 翻转为布尔值 `not services.get(2, 0)`，并将 `is_follow` 步进（当前值为 `1` 或大于 `4` 时归零，其余情况加 `1`）。完成后直接返回，不调用 `_settle_service_behaviors`。
- **其余服务**：从 `game_config.config_assistant_services_option[service_cid]` 读取选项列表 `options` 与需求列表，并通过 `setdefault(service_cid, 0)` 读取当前档位 `level`。
  - 处于末档（`level == len(options) - 1`）时，将服务档位归零。
  - 未到末档时，调用 `attr_calculation.judge_require([option_data[1][level + 1]], assistant_id, hypnosis_replace_trust_flag=True)` 校验下一档解锁条件。
  - 解锁校验失败且 `modes.debug()` 为假时，经 `ui_hooks.emit_notice(..., wait=True)` 输出失败原因并将档位归零。该函数随后直接返回，不调用 `_settle_service_behaviors`，已设置的二段行为标记保持不变。
  - 校验通过或 `modes.debug()` 为真时，将档位推进至 `level + 1`。
  - 末档归零或推进档位后，调用 `_settle_service_behaviors(assistant_id, service_cid, len(options))` 同步关联状态。

#### 附带属性变化处理 (`assistant_service._settle_service_behaviors`)
`_settle_service_behaviors(assistant_id, service_cid, option_len)` 读取当前助理在该服务上的档位 `level`，按映射表更新二段行为标记并处理同居宿舍：

- **多档位服务 (`OPTION_PREFIXES`)**：服务 4（`assistant_send_food_`）、服务 5（`morning_service_`）与服务 6（`night_service_`）先重置 `0` 至 `option_len - 1` 的全部前缀标记，再设置当前档位对应的 `f"{prefix}{level}"`。
- **开关型服务 (`SWITCH_PREFIXES`)**：服务 3（`support_service_`）、服务 7（`cohabitation_`）与服务 8（`love_support_`）先重置 `on` 与 `off` 两个标记，再按 `level` 真假设置 `on` 或 `off`。
- **其他服务**：服务 10（每周轮换）等未列入上述两张映射表的服务不修改二段行为标记。
- **服务 7（同居服务）的宿舍迁移与恢复**：
  - `level == 1` 时，先调用 `dormitory_common.register_permanent_dormitory(assistant_id)`。若角色当前住在开放普通宿舍，该函数将其写入 `chara_life.permanent_dormitory`，否则不改动。随后将 `chara_life.dormitory` 设为 `COHABIT_ROOM` 对应的地图系统路径。
  - `level != 1` 且当前宿舍等于 `COHABIT_ROOM` 路径时，调用 `dormitory_common.restore_character_dormitory(assistant_id)`。若角色未住在开放普通宿舍，该函数调用 `dormitory_common.pick_dormitory_room(room_occupancy, permanent_dormitory)` 重新分配宿舍，随后清空 `permanent_dormitory`。
  - `pick_dormitory_room` 按每间 2 人的容量从开放普通宿舍占用表中选房：若优先房间在表内且当前人数小于 2（有空床），直接返回该房间。否则按表序返回第一间人数小于 2 的房间。若全部房间满员，则回退为当前人数最少的房间（并列时取表序最前者）。

#### 助理服务触发
通过二段行为标记 (`second_behavior`) 系统触发特定的助理服务：
- `chosen_as_assistant`: 被选为助理标记
- `not_as_assistant`: 非助理状态标记
- `ai_follow_X`: 跟随服务等级标记
- `morning_service_X`: 早安服务等级标记
- `night_service_X`: 晚安服务等级标记
- `support_service_on/off`: 辅佐服务开关标记
- `cohabitation_on/off`: 同居服务开关标记
- `love_support_on/off`: 助攻服务开关标记

## 系统特点与设计思路

### 1. 模块化设计
- **UI层**: `assistant_panel.py` 负责界面展示、输入交互与早晚安预定时间设置
- **服务层**: `Script/Modules/gameplay_resolution/assistant_service.py` 独立承接无界面依赖的助理候选筛选、任免替换、每周轮换、读档修补与服务档位切换
- **数据层**: CSV配置文件提供基础数据
- **逻辑层**: 各种处理函数负责具体功能实现
- **AI集成**: 通过二段行为标记与NPC AI系统无缝集成

### 2. 灵活的配置系统
- **多选项支持**: 每个服务可以有多个等级选项
- **条件检查**: 支持基于好感度、信任度的解锁条件
- **动态配置**: 运行时可以随时调整服务配置

### 3. 状态管理
- **角色状态同步**: 助理的跟随、宿舍等状态与游戏世界同步
- **行为标记系统**: 通过二段行为标记触发相应的AI行为
- **状态持久化**: 助理配置通过存档系统持久化保存

### 4. 用户体验
- **直观界面**: 清晰的服务选项展示和状态反馈
- **智能提示**: 解锁条件不满足时提供明确的失败原因
- **时间定制**: 支持精确的时间设置（早安/晚安服务）

### 5. 扩展性
- **新服务添加**: 通过修改CSV文件和添加相应处理逻辑可以轻松添加新服务
- **AI行为扩展**: 通过二段行为标记系统可以轻松扩展AI行为
- **UI组件复用**: 使用通用的选择面板组件，便于维护和扩展

## 关键交互点

### 1. 与角色系统的交互
- 角色的基础属性（好感度、信任度）影响服务解锁
- 角色的特殊状态（异常、监禁等）影响助理候选资格
- 角色的位置信息用于跟随和同居功能

### 2. 与时间系统的交互
- 早安/晚安服务依赖游戏时间系统
- 每周轮换功能与日期系统集成

### 3. 与AI系统的交互
- 通过二段行为标记触发特定AI行为
- 跟随状态直接影响NPC的行为决策
- 助理服务与NPC日常行为相集成

### 4. 与地图系统的交互
- 同居服务涉及角色宿舍位置的变更
- 跟随功能依赖地图系统的位置追踪

### 5. 与存档系统的交互
- 助理配置和状态通过存档系统持久化
- 支持游戏重启后状态恢复

## 总结

助理系统是erArk游戏中一个设计精良的功能模块，通过CSV配置、Python逻辑处理、UI界面展示和AI行为集成，提供了完整的助理管理功能。系统具有良好的模块化设计、灵活的配置机制、清晰的状态管理和良好的扩展性，为玩家提供了丰富的助理互动体验。
