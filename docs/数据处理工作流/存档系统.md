# 存档系统

## 概述

erArk 的存档系统以单文件 JSON（`save/{save_id}/save.json`）保存内核的 `GameState` 与存档头，采用原子写盘，并以只读方式兼容版本 0 至 27 的旧存档。全局系统设置与文本生成 AI 设置独立保存在游戏根目录的 `settings.json`，不随存档。

## 核心模块

- `Script/Core/save_handle.py`：存档入口（`establish_save`、`input_load_save`）、旧存档属性读取（`load_save`）以及读档 Reset 步骤 `install_save`、`exact_stats`、`repair_installed`。
- `Script/Modules/save_load/index.py`：槽位枚举（`slots`）、格式判断（`is_json`）、`save.json` 解析（`document`）、存档头读取（`head`）与异常类 `SaveRefused`。
- `Script/Modules/save_load/kernel_state.py`：`GameState` 的 JSON 编解码（`encode`、`decode`）、原子写盘（`write`）、读档与版本校验（`read`），以及驱动内核换态的 `load`、`new_game`、`new_round`、`reset_clock`。
- `Script/Modules/save_load/legacy_pickle.py`：旧存档的受限反序列化器（`LegacyUnpickler`、`LegacyObject`、`head`、`cache`）。
- `Script/Modules/save_load/upgrade.py`：存档版本号 `CURRENT = 28` 与 JSON 升级步骤表 `STEPS`，并转发 `adopt_legacy` 中的旧存档导入函数。
- `Script/Modules/save_load/reset.py`：挂在 `kernel.Reset` 输入钩子上的步骤调度器，按 `why["cause"]` 依次运行各步。
- `Script/Modules/save_load/settings.py`：全局 `settings.json` 的载入、写盘，以及从旧存档迁入设置与 AI 设置的暂存/提交机制。
- `Script/Modules/save_load/autosave.py`：玩家睡觉结算后标记自动存档，待下一次选行动时写出 `auto` 槽位。
- `Script/UI/Panel/see_save_info_panel.py`：存档列表面板（`SeeSaveListPanel`）与单槽位操作按钮（`SaveInfoDraw`）。

## 存档文件布局

每个存档位于 `save/{save_id}/` 目录下（自动存档槽位为 `save/auto/`）：

### 当前格式（版本 28 起）

槽位目录中只有一个文件 `save.json`（`index.SAVE_FILE`），UTF-8 编码的 JSON 对象，顶层键如下：

- `version`：整型版本号，当前为 `upgrade.CURRENT = 28`（`kernel_state.JSON_SINCE = 28`）。
- `clock`：内核时钟（分钟数）。
- `characters`：各在编角色的当前行动与角色域数据。
- `data`：全局域数据。
- `head`：存档头对象，包含 `game_verson`（游戏版本文本）、`game_time`（游戏时间的 ISO 文本）、`character_name`（博士名字）与 `save_time`（真实时间的 ISO 文本），不含校验标记。

`GameState` 中的 `Fraction` 值编码为 `{"$frac": "分子/分母"}`（分母为 1 时为 `"整数"`）；普通映射不能仅含一个字符串值的 `"$frac"` 键，否则编码时报 `TypeError`。

### 旧存档格式（版本 0 至 27，只读）

旧存档槽位包含文件 `"0"`（`index.HEAD_FILE`，pickle 存档头）与文件 `"1"`（`index.CACHE_FILE`，pickle 缓存）；版本 1 至 27 另含文件 `"2"`（`kernel_state.LEGACY_FILE`，JSON 内核状态），且文件 `"0"` 与文件 `"2"` 携带同一个 `state_token` 校验标记。

读取旧存档时不会修改其任何文件，也不会顺手生成 `save.json`。只有玩家再次向该槽位存档时，才写出 `save.json` 并删除旧文件 `"0"`、`"1"`、`"2"`。

## 写盘流程

`save_handle.establish_save(save_id)` 组装 `head` 后调用 `kernel_state.write(save_id, head)`，再调用 `settings.save()`：

1. 对 `orders.settled(core.state())` 调用 `kernel_state.encode`，并合入 `"head"` 字段。
2. 写入同目录下的临时文件 `save.json.tmp`，执行 `flush()` 与 `os.fsync(f.fileno())`。
3. 调用 `os.replace` 原子替换 `save.json`。若步骤 2 或 3 抛错，删除临时文件并保留原有 `save.json` 不变。
4. 替换成功后，若槽位中残留旧文件 `"0"`、`"1"`、`"2"`，逐一删除。

## 槽位列举与存档头读取

- `index.slots()` 返回 `save/` 下按名字排序的槽位 id：目录中存在 `save.json`，或同时存在旧文件 `"0"` 与 `"1"` 时视为有效槽位。
- `index.head(save_id)`：
  - 若存在 `save.json`，经 `index.document(save_id)` 读取并把 `head["game_time"]` 解析为 `game_time.GameTime`、`head["save_time"]` 解析为 `datetime.datetime`；字段缺失或格式无效时抛 `index.SaveRefused`。
  - 否则调用 `legacy_pickle.head` 读取文件 `"0"`。

## 读档、版本校验与拒绝条件

`save_handle.input_load_save(save_id)` 调用 `kernel_state.load(save_id)`：

1. `kernel_state.read(save_id)` 读取 `(GameState | None, version)`：
   - **`save.json` 槽位**：只读 `save.json`。文件非 UTF-8、非 JSON 对象、缺整型 `version` 或缺 `dict` 类型 `head`，或 `version < 28`、`version > upgrade.CURRENT`，或解码失败（`KeyError`/`TypeError`/`AttributeError`），均抛 `index.SaveRefused`（消息包含槽位 id）。版本低于 `CURRENT` 时依次执行 `upgrade.STEPS[v]`。
   - **旧槽位（无 `save.json`）**：先读文件 `"0"` 的 `state_token`。
     - 标记为 `None`（版本 0）：若文件 `"2"` 是可读 JSON 对象则按未打标模式解码，否则返回 `(None, 0)`，随后由 `load` 构造存档头游戏时间的空 `GameState`。
     - 标记非 `None`（版本 1 至 27）：要求文件 `"2"` 是合法 JSON 对象、带整型 `version` 且 `state_token` 与存档头一致，否则抛 `index.SaveRefused`；随后校验 `1 <= version <= upgrade.CURRENT` 并沿 `upgrade.STEPS` 升至当前版本。
2. `kernel_state._reset(game, {"cause": "load", "save": save_id, "version": version})` 调用 `core.reset_state` 换入状态。在玩家选行动期间调用会中止本次选择。
3. 在 `finally` 中，若换态失败（`core.state()` 仍是换入前的对象），调用 `settings.drop_pending_ai()` 丢弃读档暂存的 AI 设置；否则调用 `settings.commit_pending_ai()` 提交并按需写盘。

## 受限旧存档读取（`legacy_pickle`）

旧存档的文件 `"0"` 与 `"1"` 经 `LegacyUnpickler` 读取，不导入或调用文件指定的任意代码：

- `datetime.datetime`：`head()` 保持普通 `datetime.datetime`；`cache()` 经 `game_time.to_game_time` 转为游戏时间。
- `VALUES` 白名单：`game_time.GameTime`、`uuid.UUID`、`fractions.Fraction`，以及 `medical_constant` 中的六个类（`MedicalPatientState`、`MedicalPatientPersonality`、`MedicalDoctorProfession`、`MedicalPatientPriority`、`MedicalMedicineResource`、`MedicalDailyCounters`）按原类型还原。
- 其余 `Script` 或 `Script.*` 全局名：一律还原为 `LegacyObject` 属性袋。带构造参数调用或收到非法状态（非字典且非 `(dict | None, slots dict)` 元组）时抛 `pickle.UnpicklingError`。
- 其他任何全局名（如 `os.system`、`builtins.eval`、`copyreg._reconstructor`）：直接抛 `pickle.UnpicklingError`。

`save_handle.load_save(save_id)` 对 `save.json` 槽位返回空字典，对旧槽位调用 `legacy_pickle.cache`；随后补齐默认 `rhodes_island = LegacyObject()`，删除 `UNSAVED_CACHE`（`map_data`、`recipe_data`、`sun_phase`、`moon_phase`、`old_character_id`、`over_behavior_character`）与 `UNSAVED_ISLAND`（`warehouse_capacity`、`people_max`、`visitor_max`、`medical_bed_limit`、`life_zone_max`、`research_zone_max`、`soldier_max`）中的字段，并把 `npc_tem_data` 里存为 `None` 的配置键补回配置模板（配置中不存在则删除）。

## Reset 步骤

`Script/Modules/save_load/reset.py` 在 `kernel.Reset` 输入钩子中按顺序运行各步（每步在 `working.based_on(new)` 缓冲区内执行并预览套用效果）：

| 步骤 | 触发原因（`why["cause"]`） | 作用 |
| --- | --- | --- |
| `install_save` | `load` | 调 `save_handle.install_save`：导入旧存档字段、迁移角色与配置、更新地图与设置、收尾幼童会话 |
| `exact_stats` | `load` | 调 `save_handle.exact_stats`（空操作占位） |
| `new_round` | `new_round` | 调 `new_round.setup` 按继承选择重建新周目数据 |
| `project` | `load`, `new_round`, `new_game` | 调 `actions.project`：无角色时按领域数据投影，有角色时处理 `open` 键 |
| `reconcile_projected` | `load` | 调 `working.reconcile`，把在编角色数据从 `roster.offstage` 移回角色数据 |
| `repair_installed` | `load` | 系统设置 14 开启时调 `Static_Check.run_load_repair()` 做保守修复 |
| `repairs` | `load` | 依次运行经 `reset.repair` 登记的读档修补函数 |
| `reconcile_roster_data` | `load`, `new_round`, `new_game` | 再次调 `working.reconcile`，保证每个角色的数据只留在一处 |
| `panel` | `load`, `new_round` | 切回场景主面板并关闭隐奸中显示非 H 指令开关 |

读取 `save.json` 槽位时运行同一套 `load` 步骤；因 `load_save` 返回空字典（含空 `rhodes_island`），各导入步骤的表现与读入空缓存的版本 27 旧存档一致。

## 存档面板

`Script/UI/Panel/see_save_info_panel.py` 提供分页存档管理界面（受 `config.ini` 中 `max_save` 与 `save_page` 控制），顶部固定显示 `auto` 槽位。每个已有槽位通过 `index.head` 渲染版本、游戏时间、博士名字与存档时间，并提供读取、覆盖、删除操作（均带二次确认）。读取被拒绝（`index.SaveRefused`）时面板显示拒绝原因并留在列表页。

## 新增持久化字段

1. 在 `Script/Modules/domains/` 对应领域模块中用 `working.register` 登记新的全局键或角色键，并提供只读接口与经 `working.put` / `working.change` 的写入接口；确保存入值都是 `core.JSON`（允许 `int`、`Fraction`、`str`、`bool`、`None`、元组与字符串键映射）。
2. 若新键缺省即可读出合理默认值，无需修改 JSON 升级逻辑；若改动了已有键的 JSON 结构，把 `upgrade.CURRENT` 加 1，并在 `upgrade.STEPS` 中为旧版本号登记对应的升级函数。
3. 如需兼容旧存档文件 `"1"` 中的历史字段，在对应领域模块的 `adopt_old_save` 中迁入，并补充单元测试覆盖编解码往返与旧存档导入。
