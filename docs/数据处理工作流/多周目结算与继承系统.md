# 多周目结算与继承系统

## 概述

多周目结算与继承系统让玩家在开启新周目时通过分配周目点数保留部分进度。系统按职责分为三个模块。

- `Script/UI/Panel/new_round.py` 负责结算面板绘制、玩家交互、重置入口 `setup()`、游戏数据重置 `_reset_game_data()` 以及换态后的唤醒报告展示。
- `Script/Modules/gameplay_resolution/new_round_service.py` 是无界面只读服务，负责周目点数汇总、继承比例与消耗计算、等级范围夹紧、成长预览、继承选择快照与能力经验展示过滤。
- `Script/Modules/gameplay_resolution/new_round_inherit_service.py` 是无界面写入服务，负责在新周目空状态上执行全局数据恢复、玩家与干员重建以及宿舍设施开放。

## 系统架构

### 1. 三模块职责与核心接口

#### `Script/UI/Panel/new_round.py`（界面与重置入口层）

`New_Round_Handle` 管理结算界面的状态与交互。主要属性如下。

- `levels`：按继承类型编号 `0` 至 `6` 排列的七项当前继承等级列表。
- `show_npc_flag`：陷落干员明细列表的展开标志。
- `show_panel_flag_list`：源石技艺与博士能力经验两块详情区的展开标志列表。
- `all_fall_chara_list`：本次结算汇总得到的陷落干员角色编号列表。
- `farewell_npc_id`：当前选中的送别干员角色编号。
- `show_world_setting`：世界设定内嵌面板的展开标志。
- `world_setting`：新周目世界设定副本，键为设定编号，值为 `0` 或 `1`。

模块内同时包含 `CharacterabiText` 与 `CharacterExperienceText` 两个预览绘制类，以及供内核重置调用的 `setup(inherit)` 和 `_reset_game_data(world_setting)`。`_reset_game_data()` 保留在面板模块中，原因是它调用了界面流程模块 `Script/UI/Flow/creator_character_flow.py` 的 `first_bonus_and_setting_updata()` 与 `game_start()`，且 `game_start()` 会延迟导入 `Script/UI/Panel/achievement_panel.py`。后端边界守卫禁止 `Script/Modules/gameplay_resolution/` 下的服务导入 `Script.UI`。

#### `Script/Modules/gameplay_resolution/new_round_service.py`（规则与查询服务）

- `points()`：汇总当前周目数、陷落干员、收藏品数量与调试标志，返回冻结数据类 `Points`。
- `rate(type_id, level)` 与 `step(type_id, level, delta)`：查询继承百分比并将等级夹紧在配置范围内。
- `maxima()`、`cost(type_id, level)` 与 `growth_preview(now_rate)`：读取博士四项属性上限，计算各类型点数消耗与成长预览值。
- `choices(levels, fallen_ids, world_setting)`：从旧周目内核状态构造传给内核重置的继承快照字典。
- `ability_groups(cid)` 与 `experience_texts(cid, now_rate)`：按角色与性别过滤能力和经验，供面板预览绘制使用。

#### `Script/Modules/gameplay_resolution/new_round_inherit_service.py`（重建写入服务）

- `rebuild(inherit)`：校验快照类型，恢复全局携带数据，依次执行 `inherit_player()` 与 `inherit_npcs()`，返回继承报告与整数键世界设定映射。
- `inherit_player(inherit)`：重建博士角色，归档旧周目履历，并按等级写入能力经验、源石技艺天赋、四项属性上限与收藏品。
- `inherit_npcs(inherit, fallen_ids)`：仅清空在编名单（`roster.active`），从只读的现有干员模板（`npc_template.table()`）重建每名干员的角色数据并使初始干员重新在编，归档全部干员旧周目履历，将通过成长阶段判定的陷落干员加回在编名单并应用好感信任、能力经验与催眠进度继承。
- `open_dormitories(chara_ids)`：为保留干员检查并开放尚未开启的宿舍设施。

### 2. 系统入口

- 玩家在源石技艺面板 `Script/UI/Panel/originium_arts.py` 中触发 `[012]Re:败者食尘`，需满足调试模式开启（`modes.debug()`），或当前游戏绝对日期已到 2020 年（游戏日历只有 3/6/9/12 月，即 2020-03-01 起）。该判定检查游戏日期而非累计游玩时长，开局日期由 `config.ini` 设定，默认为 2019-03-01。
- 确认后 `new_round_for_sure()` 创建 `New_Round_Handle` 实例并进入 `draw()` 循环。

### 3. 数据配置

- CSV 数据文件：`data/csv/New_Round_Inherit.csv` 定义继承类型、继承等级、继承比例与点数消耗。
- 配置加载：`Script/Config/game_config.py` 加载 `config_new_round_inherit`（按配置编号索引）与 `config_new_round_inherit_type_data`（按类型与等级组织的嵌套字典）。

## 周目点数系统

### 点数来源

1. **当前周目数**：公式为 `周目数 × 20`，通过 `playthrough.game_round()` 读取全局键 `calendar.round`。
2. **陷落干员**：遍历 `roster.active()` 中的在编干员，经 `handle_talent.have_fall_talent()` 获取陷落天赋编号，每名干员提供 `(天赋编号 % 10) × 2` 点。
3. **收藏品**：统计 `player_collection.get("npc_panties")` 与 `player_collection.get("npc_socks")` 下的全部条目总数，每件提供 `1` 点。
4. **调试模式**：当 `modes.debug()`（全局键 `mode.debug`）为真时，额外增加 `DEBUG_BONUS`（`9999` 点）。

### 点数消耗

各继承类型的等级上限由 `data/csv/New_Round_Inherit.csv` 定义：类型 `0` 为 `0-1`，类型 `2` 为 `0-2`，类型 `4` 与 `5` 为 `0-4`，类型 `1`、`3` 与 `6` 为 `0-5`。类型 `0` 与类型 `2` 按博士当前状态动态计费，其余类型读取配置表的 `point_cost`。

## 继承类型详解

### 1. 博士的源石技艺（Type 0，`pl_originium_arts_count`）

- **继承内容**：编号 `301-349` 的天赋。等级为 `0` 时不继承且消耗 `0` 点，等级大于 `0` 时按原值复制已拥有的该范围天赋。
- **特殊计算**：按 `ARTS_COST` 中已持有天赋的档位汇总点数消耗。
  - 初级（`304, 307, 310, 316, 331`）：每个 `10` 点。
  - 中级（`305, 308, 311, 317, 332`）：每个 `30` 点。
  - 高级（`306, 309, 312, 318, 333`）：每个 `60` 点。
  - 特级（`334`）：`120` 点。

### 2. 博士的能力与经验（Type 1，`pl_abi_and_exp_count`）

- **继承内容**：博士全部能力值（`abilities.ability(0)`）与经验值（`abilities.experience(0)`）。
- **继承方式**：按 `int(原值 × 继承比例 / 100)` 缩放后合并写入。

### 3. 博士的属性上限成长（Type 2，`pl_extra_growth_count`）

- **继承内容**：体力上限（`needs.of(0)["hit_max"]`，基础值 `1000`）、气力上限（`needs.of(0)["mana_max"]`，基础值 `1000`）、理智上限（`needs.of(0)["sanity_max"]`，基础值 `100`）与精液上限（`h_meters.of(0)["semen_max"]`，基础值 `100`）。
- **继承方式**：每项写入 `int(基础值 + (旧值 - 基础值) × 继承比例 / 100)`。
- **特殊计算**：等级为 `0` 时消耗 `0` 点。非零等级按 `GROWTH` 折算，体力与气力超出基础值部分经比例缩放后每 `50` 点消耗 `1` 周目点，理智与精液每 `1` 点消耗 `1` 周目点。

### 4. 博士的收藏品（Type 3，`pl_collection_count`）

- **继承内容**：`npc_panties` 与 `npc_socks` 两类收藏品。
- **继承方式**：分别计算上限 `int(总件数 × 继承比例 / 100)`，按干员顺序逐条复制并在累计件数超过上限后停止（触发停止的该干员条目仍会写入）。

### 5. 干员的好感与信任（Type 4，`chara_fon_and_trust_count`）

- **继承内容**：干员信任度（`relations.trust`）与对玩家好感度（`relations.favorability[0]`）。
- **前提条件**：仅适用于通过 `child_stage_gate.restore_grown_stage()` 判定的已陷落干员，按 `int(原值 × 继承比例 / 100)` 写入。

### 6. 干员的能力与经验（Type 5，`chara_abi_and_exp_count`）

- **继承内容**：干员能力值与经验值。
- **前提条件**：仅适用于上述保留的已陷落干员，按 `int(原值 × 继承比例 / 100)` 合并写入。

### 7. 干员的催眠进度（Type 6，`chara_hypnosis_count`）

- **继承内容**：干员催眠进度（`hypnosis.degree`）。
- **前提条件**：仅适用于上述保留的已陷落干员，按 `int(原值 × 继承比例 / 100)` 写入新周目状态。

## 送别系统

- 玩家可在结算面板选择一名已陷落干员作为送别对象。
- 确认进入新周目时，`start_new_round()` 在旧状态上调用 `second_behavior.character_get_second_behavior(farewell_npc_id, "new_round_farewell")`，随后调用 `talk.must_show_talk_check()` 显示送别对话。

## 新周目重置步骤顺序

1. **快照与重置触发**：`New_Round_Handle.start_new_round()` 调用 `kernel_state.new_round(self.choices())`。`new_round_service.choices()` 从旧周目内核状态提取完整继承快照字典，内核随后切换到仅含初始时钟的新空状态并按序运行重置步骤。
2. **前端重置步骤 `new_round`**：`Script/Modules/tk_ui/callbacks.py` 注册的 `build_new_round()` 调用 `Script/UI/Panel/new_round.py` 的 `setup(inherit)`。
3. **服务重建 `new_round_inherit_service.rebuild(inherit)`**：校验 `all_fall_chara_list` 与 `world_setting` 类型后，先经 `playthrough.restore_carried()` 恢复全局携带键，再依次调用 `inherit_player(inherit)` 与 `inherit_npcs(inherit, fallen_ids)`。
4. **面板重置 `_reset_game_data(world_setting)`**：重置医疗部门与难度出生设定，调用 `creator_character_flow.first_bonus_and_setting_updata()`，写入选定世界设定、新周目数（旧周目数加 `1`）与保留名册，调用 `achievement_service.settle_by_type(_("周目"))` 结算周目成就，调用 `creator_character_flow.game_start()` 完成世界初始化，最后调用 `new_round_inherit_service.open_dormitories()` 开放保留干员对应的宿舍设施。`setup()` 将继承与重置报告及新达成成就编号存入模块变量 `awakening`。
5. **后续重置步骤与唤醒展示**：内核继续执行 `project`、`reconcile_roster_data` 与 `panel` 重置步骤。状态切换返回 `start_new_round()` 的 `finally` 分支后，面板读取 `awakening` 绘制报告、等待玩家点击 `[醒来]`，再调用 `achievement_panel.draw_achievement_notice()` 展示成就通知。

## 相关常量与状态键

- **行为常量**：`Script/Core/constant/SecondBehavior.py` 中的 `NEW_ROUND_FAREWELL = "new_round_farewell"`。
- **内核状态全局键**：`calendar.round`（`playthrough.game_round()`）、`roster.active`（`roster.active()`）、`mode.debug`（`modes.debug()`）。

## UI 交互设计

1. **标题栏**：显示 `周目点数结算`。
2. **点数统计区**：显示当前周目数与点数、可折叠的陷落干员明细、收藏品统计、调试加成与总周目点数。
3. **继承选项区**：提供 `0` 至 `6` 共七个继承类别，每项含等级、比例、消耗与 `[提高]`、`[降低]` 按钮。类型 `0` 与 `1` 支持折叠展开博士详情预览，类型 `2` 与 `3` 实时显示继承预览数值。
4. **世界设定与送别区**：世界设定支持折叠编辑且不消耗周目点数，送别区可通过 `[更改送别干员]` 打开子页面选择干员。
5. **确认区**：显示总消耗与剩余点数，仅在总周目点数不少于总消耗时显示 `[确定]` 按钮。

## 开发注意事项

1. **继承快照**：跨周目数据经 `new_round_service.choices()` 生成的继承快照带入新周目的空状态。
2. **整数截断**：能力、经验、属性上限、好感信任、催眠进度与收藏品上限均采用 `int()` 截断。
3. **界面边界**：`new_round_service.py` 与 `new_round_inherit_service.py` 不导入 `Script.UI`、`Script.Settle` 或 Tk 模块。涉及 `creator_character_flow` 的开局初始化留在面板的 `_reset_game_data()` 中。
4. **配置驱动**：继承等级、比例与常规消耗由 `New_Round_Inherit.csv` 驱动，增减等级只需更新配表并重新生成配置。
