# 能力升级面板系统说明

## 概述

`Script/UI/Panel/ability_up_panel.py` 是 erArk 角色能力升级界面的绘制与输入层，负责展示能力列表、升级需求、刻印升降级页面并响应玩家选择。能力分组、需求校验与普通能力升级写入位于 `Script/Modules/gameplay_resolution/ability_up_service.py`，刻印升降级判定、报价文本与状态写入位于 `Script/Modules/gameplay_resolution/mark_change_service.py`。

## 系统架构

### 核心类与服务模块

#### 1. `Characterabi_show_Text` - 能力显示面板
**功能**: 绘制能力分组列表与刻印升降级子页面，处理玩家按钮选择与输入

**主要方法**:
- `draw()`: 调用 `ability_up_service.ability_groups()` 获取分组按钮并逐项绘制
- `mark_up_show()`: 调用 `mark_change_service.mark_up_offer()` 获取升级说明与所需宝珠并绘制确认界面
- `mark_down_show()`: 调用 `mark_change_service.mark_down_offer()` 获取降级说明、降级需求与宝珠条目并绘制界面
- `input_juel_count()`: 调用 `mark_change_service.juel_prompt()` 生成提示并通过 `mark_change_service.juel_count()` 解析夹紧用户输入
- `mark_up()`: 调用 `mark_change_service.mark_up()` 完成扣珠、升级与二段行为授予，随后调用 `second_behavior.second_behavior_effect()` 触发效果
- `mark_down()`: 调用 `mark_change_service.mark_down()` 执行降级并绘制返回的成功提示

#### 2. `Characterabi_cmd_Text` - 能力升级指令面板
**功能**: 绘制单个普通能力的升级需求详情并提交升级确认

**主要方法**:
- `draw()`: 调用 `ability_up_service.level_up_lists()`、`needs()` 与 `verdict()` 展示主次需求并绘制确认按钮
- `level_up()`: 委托 `ability_up_service.level_up()` 扣除宝珠、提升能力等级并结算技能类成就

#### 3. `Character_abi_up_main_Handle` - 主面板控制器
**功能**: 管理整个能力升级界面的外层循环，并在选择 `[返回]` 时切回场景面板

#### 4. `Character_abi_up_sub_Handle` - 子面板控制器
**功能**: 管理子页面切换控制（当前注册 `属性升级` 单页）

#### 5. `Character_abi_up_main_panel` - 主显示面板
**功能**: 组合角色信息头部、宝珠、经验、能力列表与（非角色 0 的）素质面板

#### 6. `ability_up_service` (`Script/Modules/gameplay_resolution/ability_up_service.py`)
**功能**: 无界面服务模块，提供能力列表分组与按钮数据（`ability_groups`）、主次升级需求读取与校验（`level_up_lists`、`needs`）、额外规则与调试模式综合判定（`verdict`）及普通能力升级写入（`level_up`）

#### 7. `mark_change_service` (`Script/Modules/gameplay_resolution/mark_change_service.py`)
**功能**: 无界面服务模块，提供刻印升降级资格与条件判定（`can_raise`、`raise_ok`、`lower_ok`）、升降级报价（`mark_up_offer`、`mark_down_offer`）、宝珠输入提示与校验（`juel_prompt`、`juel_count`）及刻印升降级写入（`mark_up`、`mark_down`）

## 数据结构与文件关系

### CSV 数据文件

#### 1. **Ability.csv** - 能力定义
```csv
cid,ability_type,name
能力id,类型(0:感度,1:扩张,2:刻印,3:基础,4:技能,5:性技),名字
```

**能力类型分类**:
- **0**: 感度 (皮肤感度、胸部感度、阴蒂感度等)
- **1**: 扩张 (阴道扩张、肛肠扩张、尿道扩张等)
- **2**: 刻印 (快乐刻印、屈服刻印、苦痛刻印等)
- **3**: 基础 (体力、意志、智力等基础属性)
- **4**: 技能 (料理、清洁、园艺等生活技能)
- **5**: 性技 (指技、舌技、腰技等亲密技巧)

#### 2. **AbilityUp.csv** - 能力升级需求
```csv
cid,ability_id,now_level,up_need
编号id,能力id,当前等级,升级需求
```

**升级需求格式**:
- `J0|125`: 需要0号宝珠125个
- `E0|5`: 需要0号经验5点
- `A30|3`: 需要30号能力达到3级
- 多个需求用`&`连接: `J0|125&E0|5&E10|1`

#### 3. **Mark_Up.csv** - 刻印升级数据  
```csv
cid,ability_id,now_level,second_behavior,need_state_all_value,need_state_1,need_state_2,need_state_3,need_state_4,need_juel_type
```

**字段说明**:
- `second_behavior`: 升级后获得的二段行为ID
- `need_state_all_value`: 升级需要的总状态值
- `need_state_1-4`: 具体的状态需求，支持权重调整(如 `16|0.2`)
- `need_juel_type`: 可用宝珠类型

#### 4. **Mark_Down.csv** - 刻印降级数据
用于降低负面刻印等级，需要消耗特定宝珠组合

#### 5. **Juel.csv** - 宝珠定义
```csv  
cid,name
珠id,珠名
```

**宝珠类型**:
- 感受类: 皮肤快感珠、胸部快感珠等
- 状态类: 润滑珠、习得珠、恭顺珠等
- 刻印类: 快乐珠、屈服珠、苦痛珠等

### 配置加载系统

#### `game_config.py` 中的相关配置
- `config_ability`: 能力数据字典
- `config_ability_type_data`: 按类型分组的能力列表
- `config_ability_up_data`: 能力升级需求数据
- `config_mark_up_data`: 刻印升级数据
- `config_mark_up_data_by_ability`: 按能力ID索引的刻印升级数据
- `config_juel`: 宝珠数据字典

## 核心业务流程

### 1. 普通能力升级流程

1. **生成能力列表**：`Characterabi_show_Text.draw()` 调用 `ability_up_service.ability_groups(cid)` 获取按类型分组的按钮数据。普通能力按主需求列表与 `handle_ability.extra_ability_check(..., draw_flag=False)` 决定是否附带 `(+)` 高亮。
2. **读取与校验需求**：`Characterabi_cmd_Text.draw()` 在等级低于 `MAX_LEVEL`（8）时调用 `ability_up_service.level_up_lists(ability_id, level)` 读取主需求与次需求，通过 `ability_up_service.needs(cid, need_list)` 生成展示行与宝珠消耗表，再通过 `ability_up_service.verdict(cid, ability_id, main_ok, second_ok)` 合并额外规则检查与调试模式结果。
3. **执行升级写入**：玩家确认后，面板调用 `ability_up_service.level_up(cid, ability_id, cost)`，按顺序扣除宝珠、将能力提升 1 级，并调用 `achievement_service.settle_and_notify(_("技能"))` 结算技能类成就。

### 2. 刻印系统特殊处理

#### 刻印升级流程
1. **生成升级报价**：`mark_change_service.mark_up_offer(cid, ability_id)` 调用 `second_behavior.get_now_state_all_value_and_text_from_mark_up_data(data_id, cid)` 汇总状态提供值，计算待补宝珠 `max(int(need_state_all_value - state_total), 0)`，返回说明文本、所需宝珠数与库存是否足够。
2. **写入刻印变更**：玩家确认后，`mark_change_service.mark_up(cid, ability_id, need_juel)` 扣除宝珠、将刻印提升 1 级并调用 `second_behavior.character_get_second_behavior(cid, data.second_behavior)` 授予二段行为，随后返回该二段行为标识。
3. **触发二段行为效果**：面板在 `Characterabi_show_Text.mark_up()` 中立即调用 `second_behavior.second_behavior_effect(cid, game_type.CharacterStatusChange(), [behavior_id])`。

#### 刻印降级流程
1. **展开宝珠并折减需求**：`mark_change_service.mark_down_offer(cid, ability_id)` 将宝珠条目中的占位符 `"1"` 展开为全部类型为 `0` 的状态（快感珠）并解析权重。若 `handle_premise.handle_imprisonment_1(cid)` 为真，则按关押区（设施编号 `19`）等级对应效果折减总需求 `int(need * (1 - effect / 100))`。
2. **收集宝珠用量**：面板维护各宝珠的临时使用量字典，每次输入调用 `mark_change_service.juel_prompt()` 生成预计需求提示，并用 `mark_change_service.juel_count()` 解析数字并将用量夹紧至 `[0, 当前库存]`。
3. **执行降级写入**：加权总值达到降级需求并确认后，`mark_change_service.mark_down(cid, ability_id, use)` 先将刻印降低 1 级，再按映射扣除所选宝珠并返回本地化成功提示。

### 3. 特殊能力处理

#### 技巧能力(ID=30)的额外要求
```python
if ability_id == 30:
    if character_id == 0:  # 玩家(博士)
        # 需要[指技]、[舌技]、[腰技]、[隐蔽]等级和 >= 技巧等级*2
        required_sum = now_ability_level * 2
    else:  # NPC(干员)  
        # 需要全部性技等级和 >= 技巧等级*3
        required_sum = now_ability_level * 3
```

## 与其他系统的交互

### 1. 二段行为系统 (`Script/Design/second_behavior.py`)
- `get_now_state_all_value_and_text_from_mark_up_data()`: 由 `mark_change_service` 调用，计算刻印升级的状态提供值与说明文本
- `character_get_second_behavior()`: 由 `mark_change_service.mark_up()` 调用，授予刻印对应的二段行为
- `second_behavior_effect()`: 由面板在 `mark_change_service.mark_up()` 之后调用，触发刻印升级后的二段行为效果

### 2. 属性计算系统 (`attr_calculation.py`)  
- `judge_grade()`: 将数值能力等级转换为字母等级显示
  - 0以下: G, 1: F, 2: E, 3: D, 4: C, 5: B, 6: A, 7: S, 8以上: EX

### 3. 角色信息面板 (`see_character_info_panel.py`)
- `CharacterInfoHead`: 角色基础信息显示
- `CharacterJuelText`: 宝珠信息显示  
- `CharacterExperienceText`: 经验信息显示

### 4. 素质系统 (`talent_up_panel.py`)
- `Character_talent_show_Text`: 素质升级面板，与能力面板并列显示

```
宝珠信息
经验信息
┌─────────────────────────────────┐
│ 能力:                           │
│ [感度类能力] [等级] [数值]       │

│ [性技类能力] [等级] [数值]       │
└─────────────────────────────────┘

[属性升级] 页面切换按钮
[返回]
```

### 2. 交互逻辑
- **左键点击能力**: 进入该能力的升级界面
- **刻印特殊处理**: 
  - 绿色按钮: 可升级的刻印
  - 灰色按钮: 无法升级的刻印  
  - 支持升级和降级两种操作

### 3. 性别过滤机制
`ability_up_service.ability_groups()` 在构建非刻印能力按钮时，依据角色性别与能力配置的 `sex_need` 字段过滤不匹配的能力：
```python
(sex, game_config.config_ability[ability_id].sex_need) not in ((0, 1), (1, 0))
```
角色性别为 `0` 时跳过 `sex_need == 1` 的能力，角色性别为 `1` 时跳过 `sex_need == 0` 的能力，其余值均保留显示。

```

     ↓              ↓               ↓                              ↓                               ↓

```

## 调试和开发注意事项

### 1. Debug 模式支持
- 普通能力判定：`ability_up_service._change_flags()` 与 `ability_up_service.verdict()` 在 `modes.debug()` 开启时将升级判定结果置为 `True`。
- 刻印条件判定：`mark_change_service.raise_ok()` 与 `mark_change_service.lower_ok()` 在读取配置或计算状态出现异常时回退返回 `bool(modes.debug())`。

### 2. 数据完整性检查
- 能力ID必须在配置文件中存在
- 升级需求格式必须正确
- 刻印升级数据必须完整

### 3. 扩展性考虑
- 能力类型可以通过修改CSV文件扩展
- 升级需求支持多种类型组合
- 刻印系统支持复杂的状态计算

### 4. 性能优化
- 使用字典索引提高查找效率
- 避免重复计算相同数据
- 合理使用缓存减少文件读取

## 总结

能力升级面板系统采用界面与规则分离的结构：
- **无界面服务层**：`ability_up_service.py` 负责能力列表分组、普通能力需求校验与升级写入，`mark_change_service.py` 负责刻印升降级判定、报价文本与状态写入，两模块均不导入 `Script.UI` 或 `Script.Settle`。
- **界面绘制与交互层**：`ability_up_panel.py` 保留五个面板类，负责布局绘制、玩家输入收集以及在刻印升级写入后调用 `second_behavior.second_behavior_effect()`。
- **数据驱动**：能力定义、主次升级需求与刻印升降级规则均由 CSV 构建出的 `game_config` 表提供。
