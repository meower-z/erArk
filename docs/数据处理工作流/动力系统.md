# 动力系统管理工作流

## 概述

动力系统负责罗德岛基地的供电策略、发电设施、蓄电池与调控员等运行数据，并提供完整的 UI 面板供玩家在动力调度室调整策略。系统当前覆盖传统发电、清洁能源、人力发电，以及蓄电池储能与每日结算。

## 核心代码模块

### `Script/Modules/domains/power.py`
- 管三个全局键。`base.power_strategy` 记各区块的供电策略。`base.power` 记副反应炉数量、清洁能源设施数量、蓄电池数量与四个主调控员。`base.power_storage` 记当前储能。写入整值替换键。
- `power.plant()` 与 `power.set_plant()` 读写 `base.power`。`power.storage()` 与 `power.set_storage()` 读写 `base.power_storage`。
- `power.storage_max()` 按 `base.power` 的蓄电池数量与 `Power_Storage.csv` 的单体容量算最大储能，结果不存。
- `power.operator_ids()` 取罗德岛职位名册里工作类型 11 的角色作为供能调控员名单，结果不存。
- `power.main_reactor_level()` 读动力区（设施 1）的等级作为主反应炉等级。
- `power.change_aux_reactors()`、`power.change_clean()`、`power.change_battery()` 与 `power.appoint_main_operator()` 是面板按钮用的增减与任命规则。增加的上限由动力区等级与扩展模块库存给出。
- 面板里的修改先记进玩家选择的缓冲区，在离开面板时随一个 0 分钟的 Edit 生效。

### `Script/Modules/domains/power_supply.py`
- `operator_bonus()` 用能力 48 换算调控员效率，主调控员与其他调控员的贡献不同。
- `fire_detail()` 结合副炉计划燃料、主炉等级与调控员加成算火电理论值和中间量。`fire_generation()` 只取理论值。
- `clean_generation()` 按水/风/光设施数量与调控员加成估算清洁能源，罗德岛行驶中水力与风力为 0。
- `power_consumption()` 与 `zone_consumption()` 遍历 `config_facility`，乘上 `config_supply_strategy` 的区块策略系数后得到耗电。
- `self_discharge()` 模拟逐台电池的自放电。
- `human_power()` 算一次人力发电的电量。
- `settle_day()` 按“火力发电→清洁能源→蓄电/亏电”的顺序算一天的结算数值，并扣除燃料（资源 15）。

### `Script/Settle/power_settle.py`
- `settle_power_system()` 调 `power_supply.settle_day()`，写出每日结算文本并结算发电量成就，返回缺电比例与文本。
- `store_power_by_human_power()` 处理人力发电室的绝顶发电。它把 `power_supply.human_power()` 算出的电量存进储能，并把角色的状态 12（`status_data[12]`）减半。

### `Script/UI/Panel/manage_power_system_panel.py`
- `Manage_Power_System_Panel` 负责绘制动力系统概览与供电策略、调控员、发电设施、蓄电池四个子界面，统一使用 `draw` 与 `flow_handle.askfor_all()` 处理界面与输入。
- 面板通过 `power_panel_service` 读取规则、文案与按钮可用条件，并通过 `power` 与 `power_supply` 读取概览数值或提交修改。

### `Script/Modules/gameplay_resolution/power_panel_service.py`
- 为动力系统管理面板提供无界面的纯查询、文案组装与写入封装，不导入 `Script.UI`、`Script.Settle` 或 Tk 模块。
- `zones()` 与 `step_strategy()` 按设施配置筛选非动力区区块并轮换 5 项供电策略。
- `chara_name()`、`main_operators()`、`assistants()` 与 `candidates()` 组装主调控员、辅助调控员及任命候选名单。
- `fuel_text()`、`plant_modules_text()`、`battery_modules_text()`、`main_efficiency()` 与 `aux_fuel()` 汇总燃料可支撑天数、预警提示、扩展模块已用与总上限以及反应炉配置参数。
- `aux_adjustable()`、`clean_rows()` 与 `battery_rows()` 按动力区等级与罗德岛行驶状态判定各设施行的可用条件与理论产出。`change_clean()` 与 `change_battery()` 在触达模块上限时返回提示文本。

### 关联模块
- `Script/UI/Panel/building_panel.py`：在基建面板顶部显示理论供需，点击“动力区”进入策略详情。
- `Script/UI/Panel/manage_basement_panel.py`：在“管理罗德岛系统”中调度此面板。
- `Script/Design/handle_instruct.py`：指令 `MANAGE_POWER_SYSTEM` 直接打开面板，`MANAGE_FACILITY_POWER` 处理实际调控行为。
- `Script/Design/basement.py`：`update_work_people()` 重建岗位名册（`work.roster`）。`power.operator_ids()` 从这个名册取工作类型 11 的角色。`settle_office_work()` 每天调用 `power_settle.settle_power_system()`。
- `Script/Settle/orgasm_settle.py` 与 `Script/Settle/Second_effect.py`：在高潮结算和人力发电室的 4 个第二结算效果里调用 `power_settle.store_power_by_human_power()`。

## 运行期数据结构

动力数据存在 GameState 的全局键里（`Script/Modules/domains/power.py`）：
- `base.power` 有四项，依次是已启用的副反应炉数量 `aux_reactors`、`[水力, 风力, 光伏]` 设施数量 `clean`、`[L1, L2, L3]` 电池数量 `batteries` 与火/水/风/光四个主调控员的角色 ID `main_operators`（0 为空缺）。没有这个键时读 `power.DEFAULT_PLANT`。
- `base.power_storage` 是当前储能，没有这个键时读 0.0。
- 最大储能、供能调控员名单与主反应炉等级不存，分别由 `power.storage_max()`、`power.operator_ids()` 与 `power.main_reactor_level()` 算出。
- `base.power_strategy` 是各区块的供电策略，用 `power.strategy_of(zone_cid)` 读、`power.set_strategy(zone_cid, value)` 写。策略 ID 参见 `Supply_Strategy.csv`。
- `base.stock`：资源库存，存在 GameState 的全局数据里，用 `warehouse.amount(id)` 读，用 `warehouse.add(id, n)` 与 `warehouse.set(id, n)` 写（`Script/Modules/domains/warehouse.py`）。动力系统使用的关键资源为燃料 15、副反应炉模块 51、蓄电池模块 52、清洁能源模块 53。

## CSV 与配置映射

- `data/csv/Power_Generation.csv`：`category` 列定义主反应炉、副反应炉、水力、风力、光伏、人力等条目；`level` 区分不同工况或绝顶等级；`value` 为理论产能或燃料消耗量。
- `data/csv/Power_Storage.csv`：按等级提供单体容量与自放电率；`config_power_storage_level_index` 生成映射供面板查询。
- `data/csv/Supply_Strategy.csv`：定义策略倍率（标准、超额、断电、备用、节能），对应 UI 中的循环切换。
- `data/csv/Facility.csv` 与 `Facility_effect.csv` 给出区块层级、子设施耗电与等级信息。`power_supply.zone_consumption()` 按 CID、名称与 `type` 匹配子设施，再查效果表的耗电。
- `data/csv/Resource.csv`：提供资源 ID 与说明，供燃料/模块等提示文本使用。

所有 CSV 变更需执行 `python buildconfig.py` 以生成 `Script/Config/config_def.py` 与 `game_config` 的缓存映射。

## 理论值计算流程

1. **火力发电**：
   - 主炉等级取 `power.main_reactor_level()`，即动力区（设施1）的等级 `facility.level(1, 1)`。
   - 副炉每日计划燃料 = 副炉数量 × `Power_Generation.csv` 中“副反应炉”的基础值。
   - 调控员加成：主调控员按类型专属加成，其他调控员贡献 1/5。
   - 理论发电量 = 计划燃料 × 主炉效率 × 调控员倍率。
2. **清洁能源**：
   - 读取设备数量与固定等级（目前默认 level=3），再乘以 `random.uniform(0.8, 1.2)` 模拟环境波动。
   - 行驶状态 (`location.move()` 不为 None) 时，水力/风力归零。
   - 不满足设施等级要求时（风力 <4，光伏 <5）禁止调整并显示不可用提示。
3. **耗电计算**：
   - 遍历所有 `type == -1` 的区块，读取对应设施耗电，并乘以策略系数。
   - 子设施归属通过 CID、名称包含或 `type == zone_cid` 判定。

## 每日结算流程

`basement.settle_office_work()` 每天调用 `power_settle.settle_power_system()`。结算数值由 `power_supply.settle_day()` 按以下顺序算：
1. 计算火电理论值，按实际燃料库存扣除资源 15，产能随燃料占比缩放。
2. 计算清洁能源产出并累加。
3. 比较总发电与总耗电：
   - 若不足：优先消耗蓄电池，无法覆盖时返回缺口比例（用于后续效率惩罚拓展）。
   - 若有余：先处理自放电，再将盈余充电，超出容量部分视为浪费。
4. 文本报告通过 `ui_hooks.emit_notice` 发出并等待玩家确认，可用于日志或 UI。

## UI 交互划分

- **概览页**：展示理论供需、储能、调控员、各能源设施数量，入口按钮指向四个子界面。
- **供电策略**：逐区块显示当前策略与耗电，提供 `[-]` / `[+]` 轮换策略；策略数据来源 `Supply_Strategy.csv`。
- **调控员管理**：
  - 显示总加成与数量。
  - 调用 `manage_basement_panel.change_npc_work_out` 进行岗位增减。
  - 主调控员任命通过公共 NPC 选择面板，避免多槽重复。
- **发电设施管理**：
  - 汇总燃料库存与可支撑天数。
  - 调整副反应炉数量、清洁能源设备数量（受模块与等级双重限制）。
  - 展示模块库存（资源 51/53）与设施不可用原因。
- **蓄电池管理**：
  - 调整 L1~L3 电池数量，受模块（资源 52）与区块等级限制。
  - 即时刷新总容量与自放电率。

## 人力发电逻辑

- 触发条件：角色处在人力发电室并完成不同强度的高潮（第二结算常量 `STORE_*_ORGASM_CHARGE`）。
- 绝顶等级对应 `Power_Generation.csv` 的“人力”条目；超多重绝顶以 4 次为基线并按 4 的指数级放大。
- 玩家（角色 ID 0）额外获得 10 倍电量。每次发电后，发电角色的欲情槽（状态 12，`status.of(cid)[12]`）减半。
- 可通过 `draw_flag` 控制是否即时输出提示，避免在离线或批量结算时刷屏。

## 扩展与维护建议

1. **新增能源类型**：
   - 扩充 `Power_Generation.csv`，并在 `base.power` 的 `clean` 或新加的项里存数量。`power.Plant` 与 `power.DEFAULT_PLANT` 一起改。ISLAND-27 要求 `clean` 恰为 3 项，加类型时一并改。
   - 在面板与 `power_supply` 中补充计算与显示逻辑。
2. **策略/事件联动**：
   - 可在缺电时触发随机事件。`basement.settle_office_work()` 已从当天的效率变化量里减去 `power_settle.settle_power_system()` 返回的缺口比例的一半。更强的惩罚可以接在这里。
3. **引入天气/环境系统**：
   - 当前清洁能源默认读取 level=3，可与天气模块建立映射替换固定等级与随机振幅。
4. **数据刷新**：
   - 修改 CSV 后务必运行 `python buildconfig.py`，保证 `game_config` 映射包含新条目。

## 注意事项

- UI 对齐依赖 `attr_calculation.pad_display_width()`，在新增字符串时需考虑全角字符宽度以防错位。
- `base.power_strategy` 里没有的区块读默认值，`power.UNBUILT_ZONES` 里的区块断电（2），其余标准（0）。新增默认断电的区块时把它加进 `power.UNBUILT_ZONES`。
- 版本 0 与 1 的存档把动力数据存在罗德岛对象上。读档时 `upgrade.adopt_power()` 把这些数据搬进 `base.power` 与 `base.power_storage`。`power.plant()` 原样交回存档里的 `base.power`，不补缺项。给 `base.power` 加项时要同时写存档迁移。
- 清洁能源与蓄电池的上限计算使用模块库存与区块等级叠加，进行脚本修改时注意保持这一校验顺序，防止负值或超限。
